### Changed

- **Capture dedup and `hippo learn --git` read only the copies of their texts.** They looked up each text's longest word and read every row holding it, all of the tenant's rows when the full-text index could not name the word or was out of sync. A batch now reads one query per 500 texts and gets back only rows equal to a text apart from spacing, plus sleep-merged rows holding one. A store built on `store-kit` takes whole texts in `captures.textsHolding` and `lessonWrites.textsHolding`, which replaces `textsHoldingWords`; see `docs/UPGRADING-3.0.md`.
- **Imports, `hippo sync` and the agent memory sync check for copies in one query per 500 texts.** They ran one query per text, each reading every row holding the text's longest word when the full-text index was out of sync. They now read only rows equal to a text apart from spacing, plus sleep-merged rows holding one.
- **The card list reads a page at a time.** `hippo card list` and the dashboard Board read every card of the tenant in one query. The store now reads keyset pages, newest change first; the CLI prints each page as it comes, with the same output, and `GET /api/cards` answers 1,000 cards at most, with `next_cursor` when more follow. The Board follows the cursor.
- **Sleep's graph rebuild reads back only the rows that change.** It read every entity and relation of the tenant to diff the derived graph against them; hippo.db now runs the same diff in SQL. A store built on `store-kit` implements `graphReads.graphDelta` in place of `storedGraph`, with `diffGraph` from the same entry; see `docs/UPGRADING-3.0.md`.
