### Changed

- **A store needs four groups; recall, remember and context run on it alone.** `RequiredStore` is `keyWrites`, `entryWrites`, `contextReads`, `auditLog` and the base methods. `vectors`, `vectorWrites`, `dagReads`, `graphReads`, `sessions`, `goals` and `reports` became optional: without `vectors` every recall mode ranks by BM25, and each route, MCP tool and CLI verb that needs a group checks it once at boot and answers 501 `store_not_ported` without it. `entriesWhere` moved from `reports` onto the base store. See docs/UPGRADING-3.0.md.
- **Store state lives on its owner.** Each server makes its own key verifier and local key, builds one `/ready` probe at boot and binds its MCP tools once per host; only the scrypt queue stays one per process. A server restarted in the same process proves a key again on its own budget.
- **Only the SQLite adapter opens hippo.db with a runtime, a session or the worker fence.** That right is a `DbGrant`, which the adapter alone mints. `openHippoDb` and `openHippoDbReadOnly` from `dist/db/index.js` are an unscoped connection for scripts and tests and no longer take a `grant`; `initStore` on `hippo-memory/testing` takes `{ runtime, session, busyWaitMs }`.
- **Sleep names the vector and graph groups it needs.** `SleepGroup` adds `graphReads` and `vectors`, so `SleepStore` and `SleepContext` require both, as `HippoStore` did in 2.x. `physicsSearch` with no vector source ranks by BM25 where it answered no rows. See docs/UPGRADING-3.0.md.
