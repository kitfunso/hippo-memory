### Changed

- **MCP `hippo_recall` now ranks through `api.retrieve` instead of its own copy of the recall pipeline.** It shows the same memories in the same order as before. `api.retrieve` now loads the store, applies the scope filter, runs hybrid or physics search, applies the session goal boost and strengthens the shown rows; MCP keeps its text format, budget fit, hints and Cutoff block. Three things differ. Each MCP recall now writes a recall trace with pipeline `mcp` for the list it showed, where it wrote none before. The fresh-tail and summary rows are now worked out against the top of MCP's own ranking, not a separate keyword window, so on a large store a different summary row can appear in the tail. The strength bump on shown rows is now limited to the caller's tenant. `RecallOpts` gains an optional `showRanked` callback and the `StoreRanking` type for this; leaving it unset keeps `api.retrieve` unchanged for HTTP and SDK callers.
