### Fixed

- **`hippo hook uninstall claude-code` now removes only hippo's own Claude Code hook handlers.** A handler counts as hippo's only when its command begins with a hippo command, at the start or after a `(`, with env assignments such as `HIPPO_TENANT=work` and an install path allowed in front, and with quoted text ignored. That still finds every form hippo has written, the `(hippo sleep ...)` form of hippo 0.20.3 included. It keeps a user's handler that shares a group with hippo's, one that only mentions hippo, such as `say hippo sleep` or `notify-send "Turn done (hippo sleep runs at exit)"`, and one that chains a hippo command after the user's own, such as `./backup.sh && hippo sleep`; before, all were deleted along with hippo's. The old-hook cleanup that `hippo init` and `hippo hook install` run follows the same rule. The cleanup for opencode.json keeps its own start-of-line rule.
- **A hippo handler with a launcher or env prefix is no longer installed twice, and uninstall names the ones it keeps.** `hippo init` and `hippo hook install` still see `HIPPO_TENANT=work hippo session-end ...` or `pnpm exec hippo ...` as installed, so they add no second copy. `hippo hook uninstall claude-code` leaves a handler like `nice hippo sleep` alone and prints one line to stderr that names it, so you can remove it by hand.
- **A Claude Code settings.json is read and replaced more carefully.** A file saved with a byte order mark, which Windows PowerShell 5.1 adds, is now read instead of reported as invalid, and `hippo doctor` reads it too. The file is replaced in one step, with its old mode, so a crash cannot leave it half written. A symlink, even one that points at a file that does not exist yet, keeps pointing where it did. Where a replace is refused (a bind-mounted file, a read-only folder, a Windows program holding the file) or the file has other hard links, hippo writes it in place as before. On Windows that step first waits up to a second for the program to let go. If the in-place write fails too, hippo stops with an error that names the file. A read-only settings.json is still refused, not replaced.
- **`hippo init`, `hippo hook install claude-code`, `hippo hook uninstall claude-code` and `hippo setup` now warn when settings.json cannot take hooks.** A file that is not JSON, or is `null` or an array, a `hooks` value that is `null`, a string or an array, or an event that is not a list is left unchanged, and one warning names the file. Before, `hippo setup` called such a file "already configured", a string or array `hooks` value made the install throw or report success without writing anything, and uninstall said nothing.
- **Hippo uses `CLAUDE_CONFIG_DIR` when it is set, the folder Claude Code reads, and the profile folder otherwise.** `hippo init`, `hippo hook install`, `hippo hook uninstall claude-code`, `hippo setup`, `hippo doctor` and the search for the last session's transcript look there, and an empty value keeps `~/.claude`. The default `~/.claude` now comes from the operating system's home folder, as in Claude Code, so a `HOME` that points elsewhere on Windows (Git Bash sets one) no longer sends hippo to a settings.json that Claude Code never reads. `hippo setup` names the real folder when it does not find Claude Code, and the help text for `hook` and `setup` says where the hooks go.
