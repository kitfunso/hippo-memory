### Fixed

- **`hippo uninstall` now removes only hippo's own Claude Code hook handlers.** A handler counts as hippo's only when its command begins with a hippo command, alone or after `;`, `&`, `|` or `(`, with an install path allowed in front. That still finds the `(hippo sleep ...)` form hippo 0.20.3 wrote. It keeps a user's handler that shares a group with hippo's, and one that only mentions hippo, such as `say hippo sleep` or `echo bye; hippo sleep-report-of-mine`; before, all were deleted along with hippo's. The old-hook cleanup that `hippo init` and `hippo hook install` run, and the one for opencode.json, follow the same rule.
- **A Claude Code settings.json is read and replaced more carefully.** A file saved with a byte order mark, which Windows PowerShell 5.1 adds, is now read instead of reported as invalid, and `hippo doctor` reads it too. The file is replaced in one step so a crash cannot leave it half written. On Windows that step waits up to a second for a program that has the file open, then stops with an error that names the file. A read-only settings.json is still refused, not replaced.
- **`hippo init`, `hippo hook install claude-code` and `hippo setup` now warn when settings.json cannot take hooks.** A file that is `null` or an array, a `hooks` value that is a string or an array, or an event that is not a list is left unchanged, and one warning names the file. Before, `hippo setup` called such a file "already configured", and a string or array `hooks` value made the install throw or report success without writing anything.
- **`hippo init` and `hippo uninstall` use `CLAUDE_CONFIG_DIR` when it is set, the folder Claude Code reads.** `hippo setup`, `hippo doctor` and the search for the last session's transcript look there too, and an empty value keeps `~/.claude`.
