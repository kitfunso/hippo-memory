### Documentation

- **The headline retrieval number is now `hippo recall`'s own: 85.6% R@5 on LongMemEval-S inside its default 4,000-token budget, and 96.8% with the budget lifted.** The benchmark scripts' 98.0% stays wherever it appears, labelled as their best of five settings, which are not `hippo recall`.
- **The tagline now reads "Hippo learns what is wrong and ranks it down."** It no longer says hippo stops agents repeating mistakes, which has not been measured. The npm, MCP registry, plugin and Python package descriptions and the CLI help changed to match.
- **Setup starts with `hippo init` in one project, and says what it changes before the command.** That is the store, a block in an existing `CLAUDE.md` or `AGENTS.md`, 7 Claude Code hook entries or the OpenCode plugin, the daily 6:15am run and the first-run imports, with the flag that skips each. `hippo init --scan` is a second step, and what it changes comes first there too.
- **The comparison is two tables.** The first holds buyer facts: where data lives, hosting, license, runtime, SDKs, and each tool's published benchmark with its metric. It now has rows where other tools are stronger: graph relations, a managed multi-user service and a native Python library. Hippo's lifecycle features move to a second table, labelled as design bets.
- **The README and site say what is measured.** Decay and sleep are design choices: in the mechanism audit, decay tied with decay switched off, and sleep lowered LongMemEval hit@5 by 3.6 points. Hippo has not been shown to improve agent task success. The hippocampus framing sits below the day-one facts.
- **Copy that disagreed with the code is fixed.** Sleep merges two or more related episodes, not three. After 3 bad marks and no good ones, a memory decays 1.6 times as fast and its strength is cut to an eighth. The init animation shows `hippo init` in one project with the lines it prints.
