### Added

- **`hippo projects` lists the project names a store holds, and can fold one into another.** Older versions tagged memories saved in a git worktree with the worktree's folder name, and older sleep saved merged memories as user-global. Upgrading stops new damage but leaves old rows as they were. `hippo projects --global` lists each name with its memory count, and marks a name that is a live worktree of the repo you run it in. `hippo projects merge <from> <into> --global` folds an old name into the right project: imported note copies go dormant, since the next sync re-imports any note still on disk; every other memory, dormant memory and compaction record takes the new name. `hippo projects repair --global` re-tags user-global merged memories by their parents' project. If the parents span two projects, it moves the memory to dormant, and the next sleep merges each project's parents on their own. A merged memory with no parent left is not changed. Both commands are dry runs unless you pass `--apply`. Before `--apply` writes, it copies the database to `.hippo/backups/`. It also logs one audit event with every id it touched (`hippo audit list --op project_merge`). Nothing runs on upgrade. `hippo doctor` warns when the global store has merged memories that `repair` would fix.
