### Changed

- **3.0 break: the conflict list reads one page at a time in one JOIN, and the scope rule runs in the api.** `Conflicts.list(query)` on `hippo-memory/store-kit` takes `{ tenantId, status, limit, after? }` and answers `{ rows, next }`: each conflict with both members' scope, kind, superseded mark and origin project, newest change first, and the `(updated_at, id)` position the next page starts after, or null after the last page. `Conflicts.get(tenantId, conflictId)` reads one conflict by id. `listTouchable` is gone: `listOpenConflicts` and `listConflicts` in `src/api` drop a pair the caller cannot touch and return `{ conflicts, next }`, the api form of the admin routes' `next_cursor`, with `limit` at 100 by default and 1000 at most. Listing 50 conflicts runs one statement in place of one per conflict member. `hippo conflicts`, `hippo trace` and the `hippo_conflicts` MCP tool read every page, so their output does not change; `hippo resolve` without `--keep` reads the one conflict by id.
- **3.0 break: `Conflicts.resolve` writes what the api decided.** `resolveMemoryConflict` reads the conflict by id, picks the loser, refuses to reject a personal loser and passes the store a `ConflictResolution` with both sides' scopes and the loser's fate. The store resolves only while the conflict is still open and each side still holds that scope, so a scope change between the read and the write cannot slip past the refusal. Rejecting a loser now also removes the resolver's own personal rows holding the same text, as `hippo reject` does; other people's personal rows stay.
