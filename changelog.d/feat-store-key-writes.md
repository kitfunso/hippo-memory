### Added

- **Minting and listing API keys now go through the store port, so they can run on a store other than hippo.db.** `HippoStore` gains an optional `keyWrites` member, the exported `KeyWrites` interface, with three methods. `createApiKey` inserts one key and writes its `auth_create` audit row in one transaction. `createSelfApiKey` revokes the owner's oldest live keys over the per-subject cap, inserts the new key, and writes one `auth_revoke` row per revoked key and the `auth_create` row, all in one transaction. `listApiKeys` reads one tenant's keys in the order and shape of `listApiKeyRows`. Core makes the plaintext key and its scrypt hash; a store only ever receives the hash. A store sets all three or leaves `keyWrites` unset. `sqliteStore` sets them with the queries hippo.db ran before.
- `POST /v1/auth/keys` and `GET /v1/auth/keys` need `keyWrites`, so a store that has it can now serve key mints and key lists. Under a store without it, both answer 501 `store_not_ported` before the handler runs, and a bad key still gets 401.
- `hippo-memory/server` also exports `KeyWrites`, `KeyMint`, `SelfKeyMint`, `KeyListQuery`, `NewApiKey`, `ApiKeyListItem`, `ApiKeyListRow`, `ListApiKeysOpts`, `KeysetPosition` and `StoreReply`.

### Changed

- **`authCreate`, `authCreateSelf`, `authList` and `authListRows` with `ctx.store` set run through `ctx.store.keyWrites` and never open hippo.db.** They return a promise in that case. A store without `keyWrites` rejects with `StoreNotPortedError`. With no store they run on hippo.db and return synchronously, as before. Code that types its context as the wide `Context` now gets the result or a promise of it, and should `await` the result. An add-on that calls `authCreateSelf` from a served route gets a promise, because `serve()` always passes a store.
- On the store path, a failed audit write rolls the mint back and the caller sees the error. `serve()` always passes a store, `sqliteStore` by default, so a mint over `POST /v1/auth/keys` by an admin API key now answers 500 and leaves no key when the `auth_create` row cannot be written. Before, it returned the key without the row. A mint by an admin signed in through the auth resolver already worked this way. `hippo auth create` and `authCreate` without a store still keep the key and report the audit failure.

### Tests

- **`tests/key-writes-conformance.test.ts` runs every `KeyWrites` method on hippo.db and on an in-memory store over the two-tenant fixture, and checks that values, errors and audit rows match.** It covers a mint and its row, a key id already taken, a self-mint under and over the cap, expired and revoked keys left out of the count, tenant scoping, and list filters, scope grants and paging.
- `tests/auth-key-writes-store.test.ts` checks that a mint, a self-mint and a list with a store create no hippo.db, that only the hash is stored, that a store without `keyWrites` is refused before any write, that a key a self-mint replaces is refused at once despite the verified-key cache, that a list through the store matches hippo.db for each kind of caller, and that both routes work over `serve()` on a store that has the group.
