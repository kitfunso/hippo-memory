### Changed

- **Embedding vectors live in the store instead of `embeddings.json`, and hybrid recall reads only the rows it ranks.** Schema v52 adds a `memory_vectors` table. On first open, hippo imports `embeddings.json` into it in one transaction and keeps the file as `embeddings.json.imported-<time>`; a file it cannot parse is kept as `embeddings.json.corrupt-<time>` and the next `hippo embed` rebuilds every vector. Deleting a memory deletes its vector. On a 10,000-memory store with 384-dimension vectors, one hybrid recall went from a median of 502 ms to 168 ms.
- **Hybrid recall now finds memories that share no word with the query.** Candidates are the full-text matches plus the 50 nearest vectors, so CLI recall, `api.retrieve` and the MCP recall tool can return a close paraphrase. Tenant, scope (private and quarantined scopes included) and superseded rules apply before the 50 are picked, so rows a caller may not see never push out rows it may see.
- **BM25 term weights now come from the candidate pool, not the whole store**, so some rows with near-equal scores swap places. The MCP recall `Cutoff` line now counts only rows that matched the query; before, it also counted every unmatched row as dropped.
