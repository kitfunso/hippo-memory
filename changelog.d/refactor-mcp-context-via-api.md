### Changed

- **MCP `hippo_context` now returns the same bundle as `GET /v1/context`, because it calls `api.getContext`.** It used to rebuild context itself, so every context policy change had to land twice. MCP context now merges the global store, prints the session handoff and recent session trail after the task snapshot, and hides a session digest that a printed handoff already covers. Its git query is the one `hippo context --auto` uses: changed file names, else the branch name. With no git query it lists the strongest memories instead of searching "project context general". It also records what it returned the way `/v1/context` does: retrieval stats, `last_retrieval_ids` (the target of `hippo outcome`), a recall trace and recall audit rows. An explicit `scope` still matches exactly and can admit a private scope the caller may read, and the project still comes from the served store's folder. `api.getContext` gains an `exactScope` option for this; its default behaviour for the CLI and HTTP is unchanged.
