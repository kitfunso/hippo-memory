### Changed

- **3.0 break: `Context.config` is required, and the api reads no `config.json` of its own.** Each composition root (the CLI, `serve()`, the stdio and HTTP MCP servers) loads the config once per command or request and puts it on the `Context`; `reach.global` and `reach.globalTarget` carry the global store's config beside its store, and `getContext` takes the caller's project from its surface instead of reading the working folder. `hippo-memory/store-kit` now exports `loadConfig` and the `HippoConfig` type so an integrator can build one. `docs/UPGRADING-3.0.md` has the row.
- Each composition root keeps its own parsed `config.json`: `serve()` and the CLI hold a reader keyed on the file's stamp, so two servers in one process never answer from each other's parse, and `loadConfig` reads the file on each call. `serve()` on a store other than hippo.db reads it as shared on its own requests instead of marking the folder shared for the whole process; `docs/UPGRADING-3.0.md` has the row.
- A session's end in a shared-store folder (`sharedStore: true` in its `config.json`) that has no `hippo.db` now skips, where it used to write to the global store: a shared store never reaches the operator's global store, as its recall already did not.
