### Security

- **An IPv6 client is rate-limited per /64, not per address.** One subscriber holds a whole /64, so rotating inside it used to buy a fresh bucket on the general `/v1` and `/mcp` limit. That limit, the open-stream cap for keyless clients and the MCP per-client recall state now key on the same /64 the failed-auth limit already used. IPv4 and IPv4-mapped IPv6 clients keep one bucket per address.
- **`hippo serve` can answer HTTPS itself.** Pass `--tls-cert <file>` and `--tls-key <file>`, or set `HIPPO_TLS_CERT` and `HIPPO_TLS_KEY`, and the server speaks TLS only; `serve()` takes the same pair as `tls: { cert, key }`. Giving one without the other, or a file that cannot be read, exits 1 instead of falling back to cleartext.
- **A network bind without TLS warns once at boot.** `hippo serve --host 0.0.0.0` still starts, and logs that API keys and memory text travel in cleartext unless a TLS-terminating proxy sits in front.
- **The dashboard takes its access token out of the address bar.** A page load with `?token=` now sets the cookie and answers 303 to the same address without the token, so it stays out of history, bookmarks and copied links. A visit that another site started gets a same-site refresh instead, because a browser withholds the cookie from that redirect. An API call that carries the token is answered in place, as before.
- **Every dashboard reply carries `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `X-Frame-Options: DENY`.** The policy allows scripts, styles, fonts and fetches from the dashboard itself only, with no inline script; the page shown when the UI is not built moved its styles into one block the policy names by hash.
- **Every `hippo serve` reply carries `X-Content-Type-Options: nosniff`.** Memory text is caller-written, so no browser may guess a JSON reply into HTML.
- **The Slack and GitHub webhook routes refuse before they read a body.** With no signing secret configured they answer 404 at once, and with a secret but no signature header they answer 401 at once; either way a caller still sending its body loses the connection. An oversized upload to an unconfigured webhook route therefore gets 404, where it used to get 413. A signed request now has 10 seconds to deliver its body and gets 408 after that; before, it could hold the socket open. The signature is still checked over the exact bytes sent.
- **Minting an admin key by default now says so.** `hippo auth create` without `--role` prints a note on stderr that the key is an admin key and never expires, and `POST /v1/auth/keys` without `role` logs the same at `warn` with the key id. The default itself, the printed key and the JSON reply are unchanged.
- **`hippo serve` prints at start that local requests need no API key.** One line names `HIPPO_REQUIRE_AUTH=1` as the way to require a key on every request; it is absent when that is already set.
