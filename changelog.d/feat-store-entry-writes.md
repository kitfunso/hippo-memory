### Added

- **Remember, outcome, supersede, archive and forget now write through the store port, so they can run on a store other than hippo.db.** `HippoStore` gains an optional `entryWrites` member, the exported `EntryWrites` interface, with five methods: `writeEntry`, `applyOutcome`, `supersede`, `archiveRaw` and `forget`. Each writes its rows and their audit rows in one transaction, marks a level 2 or 3 summary parent dirty when a child changes, and keeps hippo.db's rules: tombstoned values are refused with a `reject_refusal` row, raw rows are append-only, and another tenant's row or another person's personal row answers as not found. `writeEntry` refuses an id another tenant holds with `ConflictError`, where hippo.db's upsert would have moved the row into the writer's tenant. A store sets all five or leaves `entryWrites` unset. `sqliteStore` sets them with the queries hippo.db ran before.
- **`POST /v1/memories`, `POST /v1/memories/:id/archive`, `POST /v1/memories/:id/supersede`, `DELETE /v1/memories/:id`, `POST /v1/outcome` and the MCP tools `hippo_remember` and `hippo_outcome` need `entryWrites`,** so a store that has it can serve them. Under another store, `POST /v1/outcome` without `ids` still answers 501, now with the message `this store keeps no last recall: send the ids your recall returned`, as the last recall's ids live in hippo.db.
- `hippo-memory/server` also exports `EntryWrites`, `EntryWrite`, `EntryTarget`, `OutcomeWrite`, `SupersedeWrite`, `EntryRemoval`, `RawArchive`, `StoreReply`, `HippoDbContext`, `entryAfterOutcome`, `rejectionDigest`, `RejectedValueError`, `ownScopeTouches`, `BadRequestError` and `ConflictError`, so another store can apply an outcome, guard tombstones and check reach exactly as hippo.db does.

### Changed

- **`remember`, `outcome`, `supersede`, `archiveRaw` and `forget` with `ctx.store` set write through `ctx.store.entryWrites` and never open hippo.db.** They return a promise in that case, and a store without `entryWrites` rejects with `StoreNotPortedError`. With no store they run on hippo.db and return synchronously, as before. Code that types its context as the wide `Context` now gets `Result | Promise<Result>` and should `await` it, or type the context as `HippoDbContext`.
- `outcomeForLastRecall` with `ctx.store` set also returns a promise. On `sqliteStore` it runs on hippo.db as before; under any other store it rejects with `SqliteBlockedError`, as the last recall's ids live in hippo.db.
- Through a store, `remember` refuses `untrusted` and `afterWrite`, `outcome` refuses `traceId`, and `archiveRaw` refuses `afterArchive`: each writes on hippo.db's own handle, and only the connectors and the CLI send them. Under another store, `hippo_remember` skips auto-sleep, and the markdown mirrors are not written.
- `serve()` passes `sqliteStore` by default, so on hippo.db these routes now take the store path. An outcome now reads its rows inside the write transaction and commits its rewrites and audit rows together, where it read them first and each id committed alone. A forget or archive checks reach in the same transaction as the delete.
- On hippo.db, with or without a store: `archiveRaw` returns the `archived_at` it wrote, where it returned a fresh timestamp. `supersede` checks reach on the old row inside its transaction, marks the summary parent named by the live row's `dag_parent_id` rather than the copy read before the transaction, and writes the successor's markdown mirror with the origin project the row was given.

### Tests

- **`tests/entry-writes-conformance.test.ts` runs every `EntryWrites` method on hippo.db and on an in-memory store over the two-tenant fixture, and checks that values, errors, rows read back and audit rows match.** It covers summary marks, tombstone refusals and their rollback, reach across tenants and personal scopes for every method that takes a target, an id another tenant holds, repeated outcome ids, the churn-stale tag, supersede conflicts, raw-only archives and the append-only raw rule. The in-memory store is `tests/_helpers/in-memory-entry-writes-store.ts`, built only from what `hippo-memory/server` exports.
- `tests/entry-writes-store.test.ts` checks that the api writes through a store with hippo.db blocked, that a store without `entryWrites` is refused before any write, that the five routes answer 501 without the group and serve with it, that on `serve()`'s default store they write and remove the markdown mirrors, and that `hippo_remember` and `hippo_outcome` run through the store.
- `tests/mcp-store-ready-tools.test.ts` now expects `hippo_remember` and `hippo_outcome` in the store-ready list, since its stub carries every group `sqliteStore` sets. Tests that pass a no-store context to these functions type it `HippoDbContext`, a type-only change.
