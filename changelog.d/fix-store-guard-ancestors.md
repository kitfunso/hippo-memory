### Fixed

- **The test-isolation guard only watched two stores: the project-local `.hippo` under the suite's cwd and the isolated global store.** Real store resolution (`src/project-identity.ts` `findHippoStoreDir`) climbs from a child process's cwd to the nearest ancestor `.hippo`, so a child spawned below a cwd with no `.hippo` of its own could write into a store the guard never baselined, most often a live ancestor worktree's store. `tests/_real-store-guard.ts` now walks every ancestor between cwd and the same home/temp-root bounds `findHippoStoreDir` uses, watching each one whether or not it exists yet, so a leak anywhere on that chain still fails the run. The cwd's own store is watched even when cwd sits on one of those bounds, because `getHippoRoot` falls back to `cwd/.hippo` when the walk finds no marker, and an ancestor holding a plain file named `.hippo` is tolerated rather than read as a directory. The wider watch list has a cost worth knowing about: a run started from a worktree nested under another checkout now baselines that checkout's store too, so a write to it from outside the suite fails the run as a leak. The failure message names both causes instead of blaming a test. Pinned by `tests/store-guard-ancestors.test.ts`.
