### Changed

- **`hippo supersede` is now one transaction.** The new row, the link on the old row and the audit row commit together, so a failure part way leaves neither a successor without a link nor a link without a successor. The audit log gets two rows per supersede where it got three: `remember` for the new row and `supersede` for the old row. The second `remember` row, which named the old row, is gone. The old row's markdown mirror now gains its `superseded_by` line at the next mirror sync, as it already did for a supersede over HTTP.
- **`hippo supersede` no longer changes a personal row.** The CLI has no owner, so an id in someone's `personal:private:` scope now answers `Error: memory <id> not found.` with exit code 1, the same answer `hippo forget` and the HTTP and MCP routes give. Before, the CLI wrote the successor into that person's scope.
- **Internal:** `hippo remember`, `hippo supersede` and `hippo trace record` write through `api.remember` and `api.supersede` in place of the store's `writeEntry`. `RememberOpts` gains an optional `local` group (layer, pin, confidence, source, schema fit, trace outcome, source session id, and a salience gate's start-weak verdict) and `api.supersede` gains an optional fourth argument (layer, tags, pin). Both are for a caller in the same process: `POST /v1/memories`, `POST /v1/memories/:id/supersede` and the MCP `hippo_remember` tool do not read them from a client. Stored rows, the `remember` audit rows, the printed output and the exit codes of the three verbs are otherwise unchanged, which `tests/cli-write-verbs-parity.test.ts` pins.
