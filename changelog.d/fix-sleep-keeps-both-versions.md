### Fixed

- **`hippo sleep` keeps both versions of a fact until one is retired.** Sleep merged look-alike memories, such as two services on different ports or the old and new value of a changed setting, into one row that kept only the longer text, then shortened the half-life of every original. It merged the same memories again on each later sleep, so the originals faded out and one of the two values was gone. The merged row now holds the text of every original once, one bullet each, and records which memories it came from, and a memory that is already merged is not merged again. A merge takes at most 5 memories and 2,000 characters of their text, which keeps a merged row near 500 tokens; memories past either cap stay unmerged and keep their own half-life. A memory over 2,000 characters never starts a merge, and text with no word tokens, such as CJK text, never merges. A merge you rejected before this release stays rejected. The dedup step of sleep, and `hippo dedup`, removed a memory when most of its words matched another's, so a changed port, version or name counted as a copy. They now remove a memory only when its text matches another's apart from spacing.
- **Recall and context show a merged row, not the memories it holds.** `hippo recall`, `hippo explain`, `hippo context`, the API, and the MCP recall and context tools drop a memory when a merged row in the same result holds its text word for word, and drop a later copy of the same text. The check runs after the budget and `--limit` cuts, so a merged row that was cut hides nothing, and `--layer episodic` still lists the originals.
- **Learning, import, capture and sharing no longer skip a changed value as a copy of the old one; only tool-failure capture still does, on purpose.** Git learning (`hippo learn --git`, the git seeding in `hippo init`, and the MCP `hippo_learn` tool), the Claude Code memory-file import, `hippo import`, `hippo capture`, auto-share to the global store, the merge of local and global search results, and the `hippo remember` salience gate each skipped or hid a memory that looked like a stored one: by word overlap, by its first 200 characters, or by its text with punctuation dropped. So a changed port or version, or `1.5k` against `15k`, counted as a copy and the new value was never stored. They now share one check, the same text apart from spacing. The salience gate stores a near-duplicate and skips only the same text. `deduplicateLesson` in the library API is unchanged, but hippo no longer calls it. Tool-failure capture still treats two failures that differ only in numbers as one, because error text carries volatile numbers such as process ids, line numbers and timings, and that check compares a failure only with earlier captured failures.
- Merged rows written before this release keep their old text. Nothing is deleted, and text that already faded out is not restored. Their originals can merge once more, into a row in the new format.
