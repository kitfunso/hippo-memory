### Fixed

- **`hippo tokens` now counts the block `hippo compact-resume` restores after compaction.** Claude Code puts that block into the model's context, like the per-prompt hook's, but the ledger never booked it. It is now its own `compact_resume` surface, booked under the hook payload's session id, and the hook still never creates a store.
- **`hippo tokens` now counts what later model calls re-read of the hook blocks.** A block of memory text stays in the conversation, so each later model call reads it again until the host compacts. When a Claude Code session ends, hippo counts the session's model calls in its transcript and books the re-read tokens of the per-prompt hook's blocks and the compact-resume block, before sleep and capture run, dated by the day the calls happened so `--days` counts the re-reads inside its window; counting a session again replaces the earlier count. The other surfaces show sent tokens only, because their rows cannot tell a sub-agent's call from its parent's. `hippo tokens` adds a re-read column, re-read totals and how many sessions with hook blocks were counted (`--json` adds the same fields), and `hippo doctor` reports tokens sent and re-read. A session still open, or one that crashed, shows sent only. Re-reads usually bill at the provider's cached-input rate, a fraction of the full input price. Counts are still estimates (characters / 4).
- **hippo hooks that fire inside a sub-agent leave the parent session alone.** A sub-agent runs under its parent's session id, and Claude Code adds `agent_id` to a hook payload only from inside a sub-agent. If a sub-agent's compaction runs hippo's hooks, `hippo compact-resume` now restores nothing and resets nothing there, where it would have restored the parent's working state into the sub-agent and reset the parent's inject-only-on-change state. A per-prompt hook block sent inside a sub-agent is booked with no session id and never skipped as a repeat of the parent's.
