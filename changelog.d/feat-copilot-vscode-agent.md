### Added

- **VS Code's agent mode now gets hippo's pre-compact snapshot and capture after every reply.** `hooks/hippo.json` gains an `agentStop` entry, which VS Code runs as its Stop hook, and a PascalCase `PreCompact` twin, since VS Code maps no camelCase `preCompact`. The Copilot CLI may run both pre-compact entries, so `hippo pre-compact --runtime copilot` skips a snapshot the same session saved in the last 10 seconds. `hippo session-end --runtime copilot --turn` exits at once and leaves the work to a detached worker. That worker captures only the turns since the last reply and runs `hippo sleep` only at the auto-sleep threshold. It keeps one handoff per chat, rewritten each time, also after a compaction. It leaves the chat's snapshot open for the next compaction. `--turn` does nothing for any payload but VS Code's Stop, so the Copilot CLI's `agentStop` is a no-op and `sessionEnd` stays its capture.
- **One session-end worker per session.** A reply that lands while a worker runs is queued for that worker, so the last reply is never dropped. The next worker clears a dead worker's lock, and any lock older than 15 minutes, since Windows reuses process ids. Turn capture keeps its place in `~/.hippo/sessions/<session id>.cursor.json`.
- **`hippo setup` installs for VS Code when it finds a VS Code User folder**, Stable or Insiders, even with no `~/.copilot`. It adds a `hippo` server under `servers` in the User `mcp.json` and writes `prompts/hippo.instructions.md`, which VS Code attaches to every chat. It sets up the default profile only and names any profile folders it finds. An `mcp.json` with comments or a trailing comma is left as it is, with the entry printed to add by hand. An empty one gets the server. With only VS Code, setup writes no `mcp-config.json` or `copilot-instructions.md`, since only the Copilot CLI reads them. Setup says hooks need VS Code 1.109.3 or later with `chat.useHooks` on, and that older versions get the MCP server and the instructions file only. `hippo hook uninstall copilot` removes the server when hippo wrote it, and the instructions file when it is unchanged.

### Changed

- **Claude Code's pre-compact hook leaves VS Code chats to hippo.json.** With `chat.useClaudeHooks` on, which is off by default, VS Code also runs the hooks in `~/.claude/settings.json`. For a VS Code transcript, `hippo pre-compact` does nothing when `~/.copilot/hooks/hippo.json` exists, as that is the user hooks folder VS Code reads. Without it, it saves the snapshot alone. It opens no compaction record and prints no summariser instructions, since VS Code sends no PostCompact and does not read that text.
- **`hippo setup` upgrades the Copilot instructions block hippo 1.67.0 wrote to the new text,** and `hippo hook uninstall copilot` still removes a 1.67.0 block.
- **A `hippo` MCP server counts as hippo's only when it holds just the keys and values setup writes.** One with your own `env`, its own tool list or any other key stays on install and uninstall, and setup says so.
- **The 1.67.0 notes on VS Code's agent mode were wrong.** It has no tool-failure or session-end event, so `capture-error` and a plain `session-end` serve the Copilot CLI alone. It does run session start, `PreCompact` and Stop, which this release uses.
