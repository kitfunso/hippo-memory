### Fixed

- **The pre-compaction snapshot no longer gives up when the end of the transcript is all tool output, and it reads prompts typed in the VS Code extension.** Compaction usually fires right after a large tool result lands, so the last 256 KB often held no user or assistant text and hippo logged `skip: empty summary`. It now widens the window, up to 4 MB, until it has found both the last request and the last reply. The VS Code extension stores prompts as text blocks, which hippo skipped, so most snapshots from it had an empty task; those prompts are now read, with the IDE's open-file and selection context and Claude Code's "[Request interrupted by user]" notices left out. SessionEnd capture uses the same reader, so it now sees VS Code prompts too. Replayed against 939 real compactions, skips fell from 138 to 3 and snapshots with no task from 546 to 2.
- **Automatic capture no longer stores a token pasted into a prompt.** `hippo capture` (the SessionEnd hook, `--stdin` and `--file`) extracted memories from its text as written, so "we decided to use the deploy token ghp_..." became a memory with the token in it. It now runs the same secret scrub as the compaction snapshot first, and the memory keeps the decision with `[REDACTED]` in place of the token.
