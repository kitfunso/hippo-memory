### Fixed

- **Sleep no longer mixes memories from different projects in a shared store.** The global store holds memories from every project, each tagged with the project it came from. Sleep's merge, dedup, fact extraction and DAG summary steps ignored that tag. A merged row built from two projects' notes was saved as user-global, so every project's context could show it. Facts extracted from a project's memory were saved as user-global too. Dedup could delete one project's copy and keep another project's copy, which the first project's context does not show. Each step now works within one project, and each new row keeps its sources' project. A row built from memories of unknown project stays unknown, which ambient context hides by default. The markdown mirror now records an unknown project as `origin_project: null`, so a rebuild from the mirror no longer turns such a row user-global. Conflict detection now pairs two memories only when one project's context can show both: same tenant, and the same project, or a user-global memory beside a project's memory. Two projects can now hold opposite rules without being flagged. Rows merged before this change keep their user-global tag; one real store held 91 of them. Session traces still take the store's project, because session events record no project.
