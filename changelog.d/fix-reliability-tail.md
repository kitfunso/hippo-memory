### Fixed

- **`hippo codex-run` no longer crashes when its background session-end worker cannot start.** A start failure the system reports late (no memory, no process slots, a Node binary replaced mid-session) was an unhandled error, and the session's sleep and capture were lost. The work now runs in the wrapper itself before it exits, as it already did for a failure reported at once.
- **A Slack or GitHub backfill now stops with a clear error when the service sends a reply that is not what its API documents.** An HTML error page served with status 200, a `null` body, a GitHub body that is not a list, or a body over the size limit (64 MiB for a Slack page, 32 MiB for a GitHub page) used to fail with a bare parse error, or pass through as an empty page. The error now names the service, the HTTP status and the URL path, never the token or the query string. The Jev judge and the Anthropic client read their replies under a 1 MiB limit with the same shape checks; an unreadable Anthropic reply is now reported as `reply is not JSON` in place of the parser's own text.
- **A config file hippo rewrites (`settings.json`, `opencode.json`, the Codex wrapper, the workspace registry, an instructions file) now survives a power loss during the write.** The temp file is flushed to disk before it is renamed over the old one, and on Linux and macOS the folder is flushed after. When the system refuses the rename and hippo has to write the file in place, it now logs one warning that names the file and says the write was not atomic.
- **A delivery ledger failure is now logged like every other hippo diagnostic.** The four `[hippo] delivery ledger ...` lines went straight to stderr. They now carry a level (`[hippo] error: delivery ledger write failed: ...`, `[hippo] warn: delivery ledger skipped: ...`), a timestamp and, inside a server request, the request id, and they follow `HIPPO_LOG` and `HIPPO_LOG_FORMAT=json`. One of them was also missing the space after its colon.
- **`hippo dashboard` now says what to do when its port is taken, and stops cleanly on Ctrl+C.** A busy port printed an uncaught-error log line; it now prints one plain line that names the port and points at `--port`, and exits 1. Ctrl+C or a stop signal closes the listener and the store connection, then exits 0, within the 15 seconds `hippo serve` allows. The dashboard also runs under the same socket timeouts as the API server (65 s keep-alive, 70 s for headers), so an idle browser connection is no longer closed after 5 seconds, just as the browser reuses it.
