### Security

- **A member key's flagged write is held for review, and a GitHub item from an outside author is held by rule.** Over HTTP and MCP, a member's remember, and over HTTP a member's supersede (MCP has no supersede tool), into a shared scope that the instruction check flags now goes to the quarantine queue instead of being stored framed. The check reads the member's tags as well as the content, so a tag that holds an instruction holds the write. The reply carries `quarantined` (HTTP), `Quarantined [...]` (MCP), or a `Quarantined [...]` line naming `hippo quarantine approve <id>` (CLI through `hippo serve` with a member key in HIPPO_API_KEY). An admin releases it with `hippo quarantine approve <id>`. A GitHub issue, comment or pull request whose `author_association` is not OWNER, MEMBER or COLLABORATOR is held the same way, whatever its text. A store without the quarantine groups keeps the old frame, and a framed row's tags print inside the frame.
- **The operator's own CLI is not screened through `hippo serve`.** A write signed with the server's local key is no longer tagged `instruction-like`, as a direct CLI write never was.
- **Sleep frames a merged or rewritten row only when the merge forms an instruction no source held.** When sleep merges rows, or a reject or a supersede rewrites a merged row, the row prints inside the untrusted frame only if one source text, joined to the union of the sources' tags, makes an instruction that the text's own tags did not make. A row that held an instruction on its own is not framed again, so an operator's own rows stay unframed. A merged row in a personal scope is never screened. Facts that LLM extraction builds, and DAG summaries and entity profiles, keep the `instruction-like` and `untrusted-origin` tags of their sources, so they print framed when a source does.
- **A teammate whose GitHub organization membership is private can be vouched for.** Such a teammate can read as CONTRIBUTOR or NONE, so their items are held. GitHub's docs: "By default, your organization membership visibility is set to private." Either make the membership public (GitHub: "You can choose to publicize individual organization memberships on your profile."), or add the teammate's numeric GitHub user id to the new `GITHUB_TRUSTED_USER_IDS` (comma-separated). Get an id with `gh api users/<login> --jq .id`. The list takes ids, not logins, because GitHub lets anyone claim a login its owner gives up. Set it on the server, in the shell that runs `hippo github backfill`, and in the shell that runs `hippo github dlq replay`, which reads its own environment when you replay. An entry that is not a number stops `hippo serve` from starting and stops those two commands. The error names each bad entry by its position and never prints the entry, so a token pasted into the wrong variable stays out of the log. The list applies only to items from the configured GitHub server: github.com when `GITHUB_ENTERPRISE_URL` is unset, else that GHES host. An item from any other server is held by the author rule, even when its id is listed. A listed id skips only the author rule; the instruction check still holds a flagged item. Changing the list does not release items already held: approve each with `hippo quarantine approve <id>`.
- **Store port:** `ConnectorWrites` gains a required `supersedeHeld`. A store that sets the connector groups must implement it.
