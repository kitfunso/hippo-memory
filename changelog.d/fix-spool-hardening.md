### Fixed

- **A compaction summary that waited on disk is now saved once, even when two hippo processes replay it at the same time on Windows.** When the store is busy, `hippo post-compact` leaves the summary in `.hippo/compactions-spool/`, and the next sleep or post-compact saves it. On Windows two replays could both claim one file and save it twice. In a test with 2,000 files, about 700 were saved twice in each round. Replays now take turns through a lock file in that folder, and the same test saves every file once.
- **Waiting summaries are saved oldest first.** Spool file names now start with the time they were written, so a replay that runs out of time leaves the newest ones for the next run. Two summaries from one session in the same millisecond no longer share a name, so the second no longer replaces the first.
- **A summary that keeps failing is set aside instead of retried forever.** After 3 failed tries the file is renamed to `.bad` and stays in the folder for you to read. A busy store does not count as a try. A file that another program holds open is left for the next run and no longer stops the replay.
- **A summary whose write was cut off is no longer lost.** A spool file left as `.tmp` for over 10 minutes is renamed into place and saved when it is whole, and set aside as `.bad` when it is not.
- **`hippo doctor` counts spool files.** The `compactions` check now says how many summaries are waiting, how many a stopped replay left behind, and how many were set aside as `.bad`. It tells you what to do with each.
- **Session start shows one line when something went wrong.** When the last sleep failed, a replay hit a problem, or a summary was set aside, Claude Code shows you one line that points to `hippo doctor`. The sleep log still stays out of the model's context.
