### Documentation

- **`hippo init` is described as it works.** It installs hooks for Claude Code and OpenCode, adds 2 hooks to Codex's `hooks.json` when Codex is installed (Codex runs them once you trust them in `/hooks`), and adds instructions to an existing `AGENTS.md` for Codex, Cursor, OpenClaw and Pi. The README, site, npm description and setup help no longer say it wires hooks into all of them. OpenCode gets a plugin, not two entries in `opencode.json`, and it does not read OpenCode's conversation.
- **Sleep is described as it works.** It merges clusters of related memories into one, by word overlap, instead of "compressing into semantic patterns". Faded memories move to a dormant store and are deleted after 180 days, not removed at once. Sleep runs at the end of Claude Code and OpenCode sessions and in the daily job; Codex runs it only if you installed its wrapper. If `ANTHROPIC_API_KEY` is set, sleep sends memory text to Anthropic, and the help now says how to turn that off.
- **Supersession is manual.** The docs say you run `hippo supersede` or `hippo decide --supersedes`, and the `hippo decide` sample output is the real output. The mem0 comparison no longer implies hippo does it on its own.
- **Hook and session behaviour matches the code.** The per-prompt hook injects pinned memories plus the 5 newest, and reads the prompt only if `pinnedInject.promptRecall` is on. `compact-resume` prints a snapshot only when it is under 15 minutes old. `wm flush` clears working memory, and only when you run it. A failed tool call is stored word for word as an error memory.
- **Counts and lists are current.** The MCP README lists all 13 tools, `hippo hook install` and `hippo setup` help say what they write, and the OpenClaw row says the native plugin is a separate install.
- **Enterprise copy is in the future tense.** The teams page says the plugin will do what it describes, matching its "in development" label.
