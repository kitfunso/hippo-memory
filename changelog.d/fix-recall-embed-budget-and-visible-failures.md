### Fixed

- **A recall no longer hangs on a slow embedding service.** A recall that needs a query vector from a remote provider (`openai`, `voyage`, `cohere`) now waits at most 5 seconds for it in total, across every retry, then answers from keyword search alone and logs one warn line that names the provider and the budget. Before, three attempts of 30 seconds each could hold a recall for over 90 seconds. `HIPPO_QUERY_EMBED_TIMEOUT_MS` changes the budget. The in-process `local` provider has no budget, because nothing can stop it once it starts. Storing a memory keeps its long timeouts. An embedding request cut off by a network fault is now sent again, as a rate-limited one already was.
- **A memory whose stored JSON is damaged is now named in the log.** A `tags_json`, `conflicts_with_json` or `parents_json` column, or a session event's `metadata_json`, that is not valid JSON still reads as empty, and hippo now logs one warn line with the table, the row id and the column. Each damaged column of each row is reported once per process (once per store worker thread under `hippo serve`); later reads of it log at debug. The line never holds the stored text.
- **`hippo serve` now logs how a request ended after its `504` deadline reply.** A handler that fails after the reply logs one warn line, `request failed after its deadline reply`. A request that is not a `GET` and runs to its end after the reply logs one info line, `request finished after its deadline reply; its own reply was dropped`, so a write the caller was told may not have been saved can be confirmed. Both lines carry the request id, the method and the route name of the access line, and no path, body or error text.
- **A session-end step that fails is now written to the session log.** When the background worker's sleep, its capture, or its transcript scan and digest fails, hippo logs one warn line and appends the same line to the session log file (`session-end: sleep failed: ...`, `codex session-end: transcript scan or digest failed: ...`). Before, a failure outside the sleep and capture commands' own logging was written at debug only, and the worker's output goes nowhere, so nothing was left on file.
