### Added

- **`serve()` takes a `projectWriteGate` that can refuse a write under a caller's project.** It is asked before `remember()` stores a row from POST /v1/memories or MCP `hippo_remember`, after the project name passes the usual check. A string answer refuses with 403 and that text. Add-on routes call `admitProjectWrite` from `hippo-memory/server`. `hippo-memory/project-identity` now exports `assertCallerProject`. `hippo-memory/server` also exports the types `ProjectWriteCall` and `ProjectWriteGate`. Personal writes never reach the gate. An answer that is not null or a non-empty string refuses with 403 and a default text.
- **The gate has a deadline and a fixed set of statuses.** `ServeOptions.projectWriteGateTimeoutMs` (default 5000) bounds one gate call, and `ProjectWriteCall` gains `signal`, which aborts at the deadline. Statuses: 400 for a bad project name (the gate is not asked), 403 for a refusal, 500 for any other throw or rejection (the gate's text stays in the server log, never in the reply), 503 for a busy store (with Retry-After) or past the deadline. The gate gets a frozen copy of the actor, scopes included.
- **Some exported helpers never ask the gate.** `captureSessionTexts`, `preCompactForCaller`, `saveCompactionItemsForCaller`, `captureFailureForCaller` and `sessionEndHandoffForCaller` from `hippo-memory/server` store rows under a caller's project without asking it. An add-on route must call `admitProjectWrite` before them. The local CLI key (subject `localhost:cli`, no owner) reaches the gate, so a gate that should let it through must allow it.
