### Fixed

- **A dropped connection or a timed-out attempt is now retried where a replay is safe.** `fetchWithRetry` retried only 429 and 5xx answers, so one `ECONNRESET`, `ETIMEDOUT`, `EAI_AGAIN` or socket hang-up failed the call outright. `GET` and `HEAD` now retry those faults with the same backoff and attempt cap; a `POST` does so only when its caller says a replay cannot commit twice, and a refused connection or the caller's own abort is never retried. The CLI's write requests are unchanged: a `POST` that lost its connection is still not replayed.
- **The remote rerankers retry, and say when they stop and start working.** The `llm`, `jev` and `clef` rerankers each made one unretried request and warned once per process, so a long-running server gave no sign of a later outage or of a recovery. They now share one retried request bounded by the configured timeout for the whole call. A failing reranker, the local cross-encoder included, warns when it starts failing, at most every five minutes while it keeps failing, and once when it answers again.
