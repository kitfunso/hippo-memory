### Security

- **A member key changes only the team memories it owns.** Any member key could delete, archive, supersede or pin a team memory it could read, whoever wrote it, and `hippo_resolve` with `forget` could delete another person's memory. Each of these now needs an admin key or a key whose owner is the row's `owner`; a row with no `owner` is for admin keys alone. A refused write answers 404, word for word as a missing id. The CLI operator and admin keys see no change, but with `hippo serve` running a keyless `hippo forget` runs as a member, so set `HIPPO_API_KEY` to an admin key. Send `owner` on `POST /v1/memories` to keep a member's right to change its own rows; see `docs/UPGRADING-3.0.md`.
- **Goals act only inside their own tenant.** Completing, suspending or resuming a goal by id reached a goal of any tenant, held back only by the host-admin check. The store now filters each one on the caller's tenant, and a completed goal's outcome changes only that tenant's memories.
