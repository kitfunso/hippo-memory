### Security

- **Without an API key, the HTTP server answers only a local caller.** A keyless request from a loopback address counted as admin, and a web page can send one: through DNS rebinding (a hostile domain that resolves to 127.0.0.1) or by posting from another site open in the same browser. A keyless request now also needs a `localhost`, `127.0.0.1` or `[::1]` Host header, and no `Sec-Fetch-Site` or `Origin` header that points at another site; anything else gets 403. The CLI and the Python SDK send neither header, and requests with a key are unchanged. A client that reaches the server by another name, such as `0.0.0.0` or the machine's hostname, now needs a key.
- **Secrets are masked before text goes to a reranker, an embedding API or `hippo refine`.** The LLM and Jev rerankers sent the query and each candidate memory as stored, the OpenAI, Voyage and Cohere embedding providers sent memory text and queries as stored, and `hippo refine` sent the merged memory and its sources as stored. Each now passes the text through `redactSecrets` first.
- **HTTP recall caps the work one request can ask for.** `GET /v1/memories` took any positive `limit` and any `scorer_window`, so one request could make the server load and score every matching memory. `limit` must now be a whole number from 1 to 1000 and `scorer_window` at most 1000; anything else gets 400.

### Fixed

- **A recall no longer writes back the copy it read.** To count a retrieval, CLI and MCP recall and context building saved each returned memory whole, as loaded before ranking. A pin, `supersede` or outcome that landed while the recall ranked was lost, and every save refreshed `updated_at`, rewrote the markdown mirror and marked the memory's summary for an LLM rebuild at the next sleep. Recall now updates only the four retrieval fields on the live row, in one transaction. If that update fails, recall logs one line and still returns its results. The markdown mirror's retrieval count and strength now catch up at the memory's next write.
- **HTTP recall skips superseded memories.** `GET /v1/memories` returned superseded memories next to the memories that replaced them. It now skips them, as CLI and MCP recall do. `summarize_overflow` and `hippo assemble` no longer stand a superseded summary in for its facts.
- **Recall finds the current memory even when its old versions match better.** Recall cuts its candidates to a fixed window before it drops superseded memories, so when old versions of a fact outranked the current one, they filled the window and the current version never reached ranking. The window now leaves superseded memories out before the cut; `--include-superseded` and `--as-of` still load them. The CLI's "filtered pre-rank" count no longer includes superseded memories.
- **`hippo sleep --dry-run` writes nothing.** It still ran the learning step, which imports Claude Code `MEMORY.md` files and today's git commits (`autoLearnOnSleep` is on by default), so a dry run saved new memories. It now skips learning and says so.
- **Sleep never builds a new memory from a superseded one.** Merge, fact extraction, DAG summaries, summary rebuilds and entity profiles read superseded memories, so one sleep could fold an outdated claim into a new current memory. All five now skip them.
