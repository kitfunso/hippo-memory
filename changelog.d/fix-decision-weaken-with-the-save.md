### Fixed

- **A superseding decision weakens the memory it replaces in the same write as the save.** `hippo decide --supersedes <memory-id>` used to commit the new decision first and weaken the old memory afterwards, so a refused weaken left the decision recorded, the memory untouched and the exit code 0, and a retry then made a second decision. The weaken now runs inside the save: if the store refuses it, nothing is recorded, the command prints that the decision was NOT recorded and a retry is safe, and it exits 1. A retry records exactly one decision.
- **A decision superseded over HTTP or the SDK now weakens the old decision's memory.** `POST /v1/decisions/:id/supersede`, a create with `supersedesDecisionId` and `saveDecision` left the replaced memory verified; it is now stale, tagged `superseded` and on half the half-life, as the CLI already did, and the audit log gains one `remember` row for it. The replies are unchanged. A decision whose mirror memory is already gone still supersedes and weakens nothing.
