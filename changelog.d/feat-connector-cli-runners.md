### Added

- **`runConnectorCommand(ctx, argv)` on `hippo-memory/server` runs the `slack` and `github` CLI verbs on a store the caller hands in.** It takes the argv without the program name, such as `['github', 'dlq', 'replay', '12', '--force']`, and uses the CLI's own flags, help and exit codes. It resolves to that exit code. A store without the connector groups rejects with `StoreNotPortedError`. The standalone `--version`, `-v`, `--help`, `-h`, `help` and empty forms print the version or both verbs' usage and resolve to 0, as the CLI does, and `--version` after a verb prints the version without running it. A `tenantId` that is empty, blank, padded with spaces, or starts with `sess-` or `sess_`, rejects before any store call. The runner never opens hippo.db, so it writes to the handed store whatever `HIPPO_READ_ONLY` says, where the CLI's writes fail under it. These are operator calls that `ctx.tenantId` does not bound, so a host must gate them as admin. The semver promise covers the argv shape and the exit codes 0, 1, 2 and 3; the output text may change between releases. The type `ConnectorCommandContext` names what it takes: `tenantId`, `store`, `config`, and optionally `infra`, `callers` and `detached`.

### Fixed

- **GitHub dead-letter replay routes the tenant from the payload's installation and repository, as the webhook does.** Replay used to ingest every row into the caller's tenant. On an install with route rows, a replayed row now lands in the tenant today's routes name, or stays parked as `unroutable` (the retry count rises and nothing is ingested) unless `GITHUB_ALLOW_UNKNOWN_INSTALLATION_FALLBACK` is set. An install with no route rows replays into the caller's tenant, as before. A GitHub delivery whose installation id or repository full name has the wrong type now parks as `parse_error`, and a replay of such a row counts as a failed attempt with status `unhandled`.
