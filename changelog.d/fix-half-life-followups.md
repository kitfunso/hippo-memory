### Fixed

- **A new memory now starts on the `defaultHalfLifeDays` set in `.hippo/config.json`, whichever command wrote it.** Only `hippo remember` and the object writers read that setting. Superseding a memory (CLI or API), `hippo trace record`, `hippo learn --git`, `hippo capture`, the Claude Code memory and file imports, fact extraction, the DAG summaries and entity profiles, and the traces and merged memories `hippo sleep` writes all started at the built-in 365 days instead. Each now reads the store's config. `createMemory` now requires `baseHalfLifeDays`, so TypeScript code that leaves it out no longer compiles.
- **`hippo sleep` no longer retires the memory behind an incident.** Sleep keeps every memory that backs a decision, prediction or other first-class object active, because moving it to dormant storage or deleting it clears the object's link, and a restore cannot put the link back. Incidents were missing from that list, so a faded incident memory went dormant and its incident lost the link. The list now covers all eight object tables, and a test checks it against the schema.
- **`hippo trace` now shows the half-life a memory decays on.** It recomputed the figure from the 7-day base hippo used before 1.46.0 instead of reading the stored `half_life_days`, so a memory on the 365-day default showed 7 days. The text output, now labelled `(stored)`, and the `half_life_days` and `effective_half_life_days` fields in `--json` read the stored value.
