### Fixed

- **Two sleeps on one store no longer run at once.** A sleep takes a claim on the store first (an operating system lock in the new empty file `sleep.lock.db`, freed if its holder dies). A second `hippo sleep`, auto-sleep or `POST /v1/sleep` that finds it held does nothing: `hippo sleep` prints `A sleep is already running on this store (since <time>), so this one skipped consolidation.` and exits 0, the server answers 200 with `alreadyRunning` and every count at 0, and an auto-sleep logs one line (the MCP stdio host also waits a minute before it tries again). Before, both sleeps sent the same memories to the model, so the model was paid twice and a fact it worded two ways could be stored twice. The `hippo sleep` steps before consolidation (git learn, agent-note import, compaction replay, repairs) still run, a dry run is never refused, and the library `consolidate()` is not guarded.
