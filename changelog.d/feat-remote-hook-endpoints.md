### Added

- **`hippo serve` answers the per-prompt hook for laptops with no store of their own.** `POST /v1/hooks/prompt` takes `{"session_id", "project": {"name", "legacy_name", "aliases"}, "payload"}`, where `aliases` (optional, up to 8) are the project's other names, such as its remote id when a `.hippo-project.json` names it, and `payload` is Claude Code's UserPromptSubmit input, and returns `{"arm", "stdout"}`. `stdout` is the text `hippo context --pinned-only --include-recent 5 --format additional-context` would print for that session in that project, read from the served store, with the project taken from the request and the tenant from the API key. The pilot arm and the token ledger rows (inject, prompt recall and skip) are written on the server under the request's session id; `arm` is `treatment`, `holdout` or `null` when the store's holdout rate is 0, and a holdout session gets an empty `stdout`. Any other event is a 404. The route needs a key like every other `/v1` route.
- **`hippo-memory/project-identity` exports `resolveProjectIdentity`,** so a hook client can name the project it runs in the same way the local hook does.
- **`hippo-memory/json-hooks` exports the Claude Code hook installer,** so a client that replaces hippo's local hooks removes them with the same code `hippo init` adds them with.
