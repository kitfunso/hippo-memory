### Added

- **`serve()` takes a `routes` option, so an add-on can mount its own POST `/v1` routes.** Each route is `{ path, handler }`. Core checks the API key and parses the JSON body, then sends the handler's return value as a 200 JSON reply; an `HttpError` the handler throws becomes that status with an `{"error"}` body. `serve()` refuses to start on a path that is not a plain `/v1/` path, is listed twice, or is already served by a core POST route or a public connector webhook, so an add-on cannot shadow a core route. Under a store other than `hippo.db`, an add-on route answers 501 after the auth check, like any route not yet ported. `GET` add-on routes, query strings and routes that run before the store is ready are not part of this seam.
- **`hippo-memory/server` exports `promptHookContext`, `HttpError` and the types `AddonRoute`, `AddonCall` and `JsonValue`.** `promptHookContext(ctx, { sessionId, project, payload })` returns the text `hippo context --pinned-only --include-recent 5 --format additional-context` would print for that session in that project, read from the store behind `ctx`, with the pilot arm and the token ledger rows (inject, prompt recall and skip) booked there under the session id. A holdout session gets an empty `stdout`; `arm` is the ledger's `hippo` or `holdout`, or `null` when the store's holdout rate is 0. An add-on route uses it to answer the per-prompt hook of a laptop that keeps no store of its own.
- **`hippo-memory/project-identity` exports `resolveProjectIdentity`,** so a hook client can name the project it runs in the same way the local hook does.
- **`hippo-memory/json-hooks` exports the Claude Code hook installer,** so a client that replaces hippo's local hooks removes them with the same code `hippo init` adds them with.
