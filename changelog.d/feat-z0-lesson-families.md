### Added

- **The Z0 runner now teaches and checks lessons.** A tasks file can define lesson families: a rule, its reason, a key phrase, a checker script, and at most one reversal. Each seed draws one task order per sequence, shared by every arm, that keeps each teach at least 2 tasks before its first apply and keeps a lesson's key phrase out of every earlier prompt. A teach task always gets one resume, a correction when its first check fails and a confirmation otherwise; an apply gets a correction only when its first check fails. Checkers grade the change between `Z0_PRE_COMMIT` and `Z0_POST_COMMIT` and read the agent's shell commands, subagents' included, from `Z0_COMMANDS`; a broken checker makes the record `invalid: 'checker'`, never a verdict, and an agent that breaks its own workspace repo makes it `invalid: 'workspace'` while the run goes on. A resume cut off by a plan limit is undone exactly before it reruns. New arm A4 writes every taught lesson into `CLAUDE.md`. `--screen` runs A0 and A4 on each family's screen task and writes the keep, drop and undecided lists to `screen.json`. Records and `plan.json` cells now carry the `z0-record/1` fields the Z0 analyzer reads, `set`, `kind` and `familyId` included.
