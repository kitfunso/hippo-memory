### Added

- **Faded memories go dormant, not gone (on by default).** Sleep now moves a memory that faded below the decay threshold into a dormant store instead of deleting it. A dormant memory leaves recall and context exactly like a deleted one and sits out every later sleep, so what your agent sees does not change. `hippo dormant` lists and searches them (`--json`, `--limit`, `--global`), `hippo dormant restore <id>` brings one back with a fresh recall clock, and `hippo dormant forget <id>` deletes one for good; `hippo forget` on a dormant id points at those two. Every restore writes a `dormant_restore` audit row (reason, strength when it went dormant, days dormant), the "forgot it, then needed it" signal a learned lifecycle trains on. Guardrails: a faded memory the secret detector flags is deleted, never kept dormant; a dormant memory nobody restores within `dormant.retentionDays` (default 180, `0` keeps them forever) is deleted for good, even after the feature is switched off; `hippo reject` removes dormant copies of the rejected value, and a restore goes through the rejection guard. `hippo sleep` prints how many memories went dormant or expired, and `POST /v1/sleep` returns them as `dormant` and `dormantExpired`. To delete faded memories straight away as before, set `{"dormant":{"enabled":false}}` in `.hippo/config.json`. A malformed `dormant` setting prints a warning and falls back to the default. Schema v44 adds the `dormant_memories` table; an older binary ignores it and keeps deleting faded memories.
- **Token ledger and `hippo tokens` (ROADMAP TE0).** Every block of memory text hippo hands an agent is recorded with its surface (per-prompt hook, `hippo context`, `hippo recall`, MCP `hippo_recall`/`hippo_context`, HTTP recall, context and assemble), session and estimated token count, never the text. `hippo tokens` prints totals per surface for the last 30 days (`--days`, `--json`, `--global`); rows older than 90 days are pruned. Schema v45 adds the `token_ledger` table. `estimateTokens` is now defined once and used everywhere, instead of six inline copies.
- **The per-prompt hook sends a block only when it changed (ROADMAP TE1, TE2).** The `UserPromptSubmit` hook (`hippo context --pinned-only --format additional-context`) no longer renders live strength percentages, so an unchanged set of memories renders byte-identically. When the hook payload carries a session id, a block identical to the one the session already received is skipped and logged as tokens saved; it is resent every 10 skips (`pinnedInject.refreshTurns`, `0` never resends) and after compaction (`hippo pre-compact` and `hippo compact-resume` reset it). Set `{"pinnedInject":{"skipUnchanged":false}}` to send it every turn as before. A manual run without a payload session id always prints.
- **Token-efficiency eval harnesses (ROADMAP TE3, TE4, TE5).** `scripts/token-eval/replay.mjs` replays sessions through the real per-prompt hook and prices what hippo itself injects with a prompt-cache model; on three synthetic traces, skipping unchanged blocks cut hippo's own injected text by 85-90% (this is hippo's overhead, not a saving on the agent's work). `scripts/token-eval/claude-usage.mjs` reads Claude Code's own session records on the user's machine (API-billed usage per message, deduplicated by message id, subagents included) and joins them to hippo's ledger by session id. `scripts/token-eval/budget-curve.mjs` sweeps the memory budget on LongMemEval-format data against recency, full context and no memory. `scripts/token-eval/ab-analyze.mjs` computes cost per resolved task, resolve rate and work avoided with bootstrap CIs for the pre-registered agent A/B (`docs/evals/2026-09-23-te5-token-ab-preregistration.md`). Shared statistics live in `src/eval-stats.ts`. See `benchmarks/token-eval/README.md`.
- **Runner for the with-and-without-hippo A/B (ROADMAP TE5).** `scripts/token-eval/ab-run.mjs` runs real Claude Code sessions (`claude -p --output-format json`) on sequences of coding tasks in four arms (no-memory, hippo, random-text, stale-memory), records the API usage and list-price cost Claude Code reports, grades with hidden tests, and writes records for `ab-analyze.mjs`. Workspaces carry history only up to each task's base, and the user's own hooks and MCP servers do not load. `scripts/token-eval/make-tasks.mjs` drafts tasks from a repository's history, keeps only those whose tests fail before the fix and pass after it, and marks every prompt for review.
- **`hippo doctor` (and `--json`).** A read-only health check: Node version, project or global store, database schema, memory and dormant counts, last sleep, Claude Code hooks or plugin, embeddings, and memory text sent in the last week. Every warning and failure names the command that fixes it, and any failure exits 1, so an agent can install hippo and check its own work.
- **Agent-friendly install.** `llms-install.md` walks an AI agent through installing, wiring in and verifying hippo. `npx -y hippo-memory mcp` needs no global install: with no store anywhere, the MCP server's first tool call creates the global store instead of failing. A `.claude-plugin/marketplace.json` at the repository root makes `/plugin marketplace add kitfunso/hippo-memory` work, and `server.json` plus `mcpName` in `package.json` prepare the listing in the official MCP registry.
- **After compaction, Claude Code tells you what hippo saved.** Compaction used to show only "PreCompact [...] completed successfully", so nothing said memory was being saved. A new `PostCompact` hook runs `hippo post-compact`, which prints "Hippo saved your task snapshot and N new memories before compacting. The snapshot is restored into the new context." It prints nothing when nothing was saved, and it shows each message once, only in the session that compacted. `hippo pre-compact` still prints nothing, because Claude Code passes PreCompact output to the summarising model as extra instructions. `hippo hook install claude-code`, `hippo init` and the plugin add the hook, and `hippo doctor` flags it when missing. It needs a Claude Code version with the `PostCompact` hook; the saving itself works without it.
- **Releases are published from CI with npm provenance, and there is a `stable` channel.** Pushing a `v<x.y.z>` tag runs `.github/workflows/npm-publish.yml`. It checks the tag against `package.json`, runs the full pre-publish gate and publishes with `--provenance`, so `npm audit signatures` can verify each release. `hippo-memory@stable` points at a release that has been out for 7 days with no fix release on top. `SECURITY.md` explains how to report a vulnerability privately. See `docs/release-policy.md`.
- **Changing the default half-life moves existing memories too.** Each memory stores its own half-life, so a new `defaultHalfLifeDays` used to reach only new memories and leave a store mixing both. `hippo sleep` now first moves memories still on the old base to the new one. Memories hippo has shortened keep their value, and so do memories with a fixed half-life of their own (decisions, incidents, customer notes). The rescaled ids go to the audit log (`half_life_migrate`), setting the old value back moves them back, and a dry run writes nothing. `hippo watch` now uses the configured default instead of a hard-coded 7 days.
- **Failed tool calls become error memories on both install routes (`hippo capture-error`).** `hippo hook install claude-code` and `hippo init` now add the `PostToolUseFailure` hook the plugin had, and both run `hippo capture-error`, which skips interrupts, declined permissions, searches that found nothing and `grep`/`find`/`diff`-style exits, stores a repeated failure once, and marks what it stores `observed` instead of `verified`. The plugin's bash script is gone, so capture also works on Windows without bash. The plugin is now 0.6.0.
- **`hippo doctor` names each missing Claude Code hook**, including compaction (`pre-compact`, `compact-resume`) and failed-tool capture, and `hippo hook install claude-code` adds only what is missing.

### Security

- **A member key can no longer read a private scope by naming it.** Recall and assemble (HTTP, MCP and the api layer) refuse an explicitly requested `<source>:private:*` or quarantined scope (`unknown:legacy`) for a member key with 403. Before, any key in a tenant could read every private Slack channel or GitHub repo by passing its scope string. Admins, the local CLI and loopback without a key keep full access; per-scope grants for member keys are ROADMAP Part VIII EI2. (Minting and revoking keys as a member was closed in 1.45.0.)
- **MCP over HTTP runs a member key as a member.** The MCP tools built an admin actor for every caller; they now use the role the HTTP transport authenticated. Stdio MCP is the local operator and still runs as admin.

### Changed

- **The default half-life is 365 days, up from 7.** A pre-registered decision on hippo's lifecycle eval found that 7 days put the current version of a fact in the top five far less often: 29% against 75% at 365 days. It was confirmed on a second set of 20 seeds that nothing had tuned, under the audit's own guards. 730 days and decay switched off both tied with 365 (`docs/evals/2026-09-24-decay-default-result.md`). On LoCoMo, 365 days also narrows hippo's retrieval gap to plain BM25 from 6.9 points to 1.0.
  - **Migration:** the first `hippo sleep` after upgrading moves memories still on the old 7-day base to the new one, once, in one transaction, keeping the days recall added and logging each id with its old value. Memories hippo shortened and memories with their own fixed half-life keep their values. New stores start on 365 days.
  - **What changes for you:** unused memories now fade over years instead of weeks, so sleep deletes far less. For shared servers, see the store-size check in the result file.
  - **Keeping the old behaviour:** set `{"defaultHalfLifeDays": 7}` in `.hippo/config.json`.
- **Physics scoring is off by default.** Its paired ablation (`benchmarks/physics-ablation/`) measured it worse than classic hybrid search on every metric with the confidence interval excluding zero (MRR 0.68 vs 0.84, R@5 74% vs 84%), and the 2026-09-23 mechanism audit measured it 22.2 points worse at hit@5 on LongMemEval (CI [-26.6, -17.8]), yet `physics.enabled` defaulted to `'auto'`, which switched it on for every store with embeddings. Recall with embeddings now uses classic hybrid search. Set `{"physics":{"enabled":"auto"}}` to opt back in. The micro-eval fixtures `dlpfc-goals` and `ofc-utility` were calibrated on physics ranking and are recalibrated for hybrid ranking; the mechanisms they test are unchanged.

### Fixed

- **Sleep never retires a memory that backs a decision, prediction, process, policy, skill, project brief or customer note.** Moving one to the dormant store, or deleting it, cut the object's link to its memory (`ON DELETE SET NULL`), and a restore could not bring the link back. For example, `hippo decide --supersedes <memory-id>` could no longer find the decision. These memories now stay active; the object they back manages their lifecycle.
- **`hippo dormant forget` counts toward "Total forgotten" in `hippo status`,** like `forget` and archiving a raw memory.
- **Compaction in a project without its own store saves to the global store.** `hippo pre-compact` skipped every project that had never run `hippo init`, even when a global store existed, so nothing was saved there. It now falls back to the global store, as failed-tool capture already did, and `hippo compact-resume` restores from the same store. With no store anywhere, both still create nothing.
- **Compaction no longer stores Claude Code's own boilerplate.** Transcript mining (compaction and session-end capture) treated Claude Code's compact summaries, meta lines and slash-command lines (`<command-name>`, `<local-command-stdout>`) as things the user said, so a `/compact` stored "The messages below were generated by the user while running local commands" as a memory. They are skipped now.
- **Re-running `hippo init` adds hooks a newer hippo introduced.** When `CLAUDE.md` already held the hippo block, init skipped the Claude Code settings hooks entirely, so an older install never gained the compaction and failed-tool hooks.
- **The README lists the MCP server's real tools.** It named 7, one of them not a tool, while the server exposes 13; a test now keeps the list equal to the server's `tools/list`.
- **`hippo learn --git` honours `gitLearnPatterns`.** A custom pattern list in `.hippo/config.json` applied only to the MCP `hippo_learn` tool; the CLI always used the built-in list. Both now read the config (its default is the same built-in list).
- **MCP tool descriptions state the real budgets.** `hippo_recall` and `hippo_context` advertised a 1500-token default while using `defaultBudget` (4000) and `defaultContextBudget` (3000).
