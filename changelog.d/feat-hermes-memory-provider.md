### Added

- **A Hermes Agent memory provider ships in the package.** `extensions/hermes-memory-provider/hippo/` is a Hermes plugin. Before each local turn it gives Hermes the pinned rules and the memories that match the prompt, it gives the agent `hippo_recall`, `hippo_remember` and `hippo_outcome`, and it captures each local session into the global store. Gateway chats, cron jobs and Kanban workers get none of this unless `memory.hippo.platforms` in the Hermes `config.yaml` lists them. With the folder in the profile's `plugins/`, `hermes config set memory.provider hippo` turns it on.
- **`hippo recall`, `hippo outcome` and `hippo context` take `--global`.** With the switch each verb reads or writes the global store (`$HIPPO_HOME` or `~/.hippo/`) alone, whatever folder it runs in, as `hippo sleep --global` already does. Without it nothing changes. A caller with no project folder, such as a chat host, can now recall, mark outcomes and build hook context from the one store it writes to.
- **`hippo outcome --id <id>` can be given more than once.** One call marks every id and prints the total applied. An id outside the caller's tenant is skipped, as before.
- **`collectSessionTurns` reads plain `{"role", "content"}` lines.** A JSONL line with no `type` key, a `role` of `user` or `assistant` and a non-blank string `content` now gives one turn, so a chat host can hand `hippo capture --transcript` its messages as they are. Lines with a `type` (Claude Code, Codex, Copilot) read as before. `collectSessionTurns` is exported from `hippo-memory/session-text`, so an integrator's transcript with such lines now gets turns where it got none.
- **`hippo import --agents` reads Hermes Agent memories.** It imports the entries of the active profile's `memories/MEMORY.md` and `memories/USER.md`; `hermes` is the tool id for `HIPPO_AGENT_MEMORY_TOOLS` and `agentMemories.tools`.

### Fixed

- **`--x=` with an empty value on a repeatable flag now counts as given with no value, as `--x` does.** `hippo outcome --good --id=` fails with "--id requires a value" again, where it marked the last recall's memories. A missing global store now says `No global hippo store at <root>. Run \`hippo init --global\` first.`
- **A capture into the global store with no project no longer pins the rules it finds.** This holds for `hippo capture --global`, and for a Claude Code or Codex session end in a folder with no project and no store of its own. Those rules used to reach every project's prompts. They are now stored as plain captured items, so recall still finds them. A capture that names a project, and a capture into a project's own store, pin as before.
