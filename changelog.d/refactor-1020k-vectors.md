### Changed

- **3.0 break: the embedding index is one session, opened once and stepped by kind.** `embeddingIndex.open()` answers a session as plain data, `{ id, key }`, and `embeddingIndex.step(id, step)` takes one step on it: `lock`, then `begin`, `stage` and `commit` for a rebuild, and `close`, which drops an uncommitted rebuild and releases the lock. Eleven more kinds replace the other old methods, and `entryCount` is gone. The lock token and the staged vectors stay on the thread that opened the session, so under `serve()` every step runs on the writer thread. `hippo embed` writes the same index, model identity and log lines as before.
- **3.0 break: `vectors.stored(part, ids)` replaces `storedVectors`, `physicsParticles` and the `vectorViews` group.** `stored('vectors', ids)` answers `Float32Array` views on hippo.db, and a store you build may answer `number[]`. `'vectorViews'` is no longer an optional group.
- **3.0 break: `graphReads.graphRows` takes a walk query.** `{ by: 'memory' | 'entity', ids }` and `{ by: 'neighbor', ids, limit }` replace `entitiesForMemories`, `entitiesByIds` and `neighborRelations`, with the same rows in the same order. The vector and graph port groups go from 32 methods to 10.
