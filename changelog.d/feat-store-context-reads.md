### Added

- **`getContext` now reads through the store port, so `GET /v1/context` and the `hippo_context` MCP tool can run on a store other than hippo.db.** `HippoStore` gains an optional `contextReads` member, the exported `ContextReads` interface, with four reads: `unfinishedHandoff`, `ambientCandidates`, `contextCandidates` and `ambientTallies`. Each takes the tenant id first. The active task, its handoff and its events come from the base `continuity` read that recall already uses. A store sets all four or leaves `contextReads` unset. `sqliteStore` sets them with the queries hippo.db ran before.
- **`GET /v1/context` and `hippo_context` name the `contextReads` group.** Under a store without it, both answer 501 `store_not_ported` (MCP error -32603) before the handler runs, and `tools/list` leaves `hippo_context` out. A query under an embedding provider also needs the `vectors` group, and answers 501 without it.
- `hippo-memory/server` exports the rules a store needs to answer these reads as hippo.db does: `passesScopeFilterForRecall`, `RECALL_DEFAULT_DENY_SCOPES`, `SECRET_TAGS`, `tallyAmbientEntries`, `ftsTermParts` and `rarestFtsQuery`. `rarestFtsQuery` builds the prompt-recall search from each term part's document count, and hippo.db's own search now uses it too.
- It also exports the types these reads take and return: `ContextReads`, `AmbientCandidateRequest`, `AmbientLoadResult`, `AmbientRecallRequest`, `ContextCandidateFilter`, `RecentOrigins`, `AmbientStoreFilter`, `AmbientTallies`, `SessionEvent`, `TaskSnapshot` and `SessionHandoff`.

### Changed

- **`getContext` with `ctx.store` set to a store other than hippo.db reads and writes only through that store, and never opens hippo.db.** Its `recall` audit row goes through `appendAuditEvents`, the trace and the retrieval strengthening through `finishRecall`, and the recall counter through `bumpRecallStats`. It does not write the last-recall ids (`last_retrieval_ids`, `last_trace_id`), which only `POST /v1/outcome` reads and no other store serves yet, and it does not write the active-task mirror file. It never reads the operator's global store. A store without `contextReads` rejects with `StoreNotPortedError`. With no store, or with `sqliteStore`, `getContext` runs on hippo.db as before.
- `getContext` keeps only the caller's tenant's rows from `ambientCandidates`, and checks pins and recent rows against its own scope, project and secret rules again. A store that returns too much cannot widen what the caller sees. On hippo.db nothing changes.
- When a store fails to write the trace for an empty context, `getContext` logs the error and still returns, as it does on hippo.db.

### Tests

- **`tests/context-store-path-parity.test.ts` checks `getContext` on hippo.db, with and without `sqliteStore`, against golden files in `tests/fixtures/context-store-path/`.** The code before this change wrote them. Each golden holds the result, the rows and meta written, the stats, and the files written beside hippo.db, with the operator's global store present. The new code must match each one exactly as JSON.
- The same file runs each case on an in-memory store with hippo.db blocked and a local test embedding provider. The result and the rows written must equal hippo.db's, and the test checks which store reads each case made, so the vector search, physics, `continuity` and `unfinishedHandoff` all run through the store.
- `tests/context-reads-conformance.test.ts` runs each `ContextReads` method on hippo.db and on the in-memory store over the two-tenant fixture, and checks that values, errors and audit rows match. It also checks that no read returns another tenant's row, that prompt recall and the candidates leave out rows the default scope rule refuses, and that the tallies leave out another project's secret-tagged row.
- `tests/context-reads-served.test.ts` compares the route and the tool over `serve()` on both stores. `tests/mcp-store-ready-tools.test.ts` expects `hippo_context` among the store-ready tools. `tests/prompt-recall.test.ts` covers `ftsTermParts` and `rarestFtsQuery`.
