### Added

- **Codex gets hippo's memory through its own hooks.** `hippo hook install codex`, and `hippo setup` when it finds Codex, add two hooks to Codex's `hooks.json` (`$CODEX_HOME/hooks.json`, else `~/.codex/hooks.json`). `hippo init` and `hippo init --scan` add them when Codex is installed (that folder exists) and the project has `AGENTS.md` or `.codex`; init never creates the folder. A `UserPromptSubmit` hook runs the same `hippo context --pinned-only` command as Claude Code's, so your pinned memories plus the five most recent ones reach every Codex prompt as developer context without the model having to run a command. A `SessionStart` hook with the matcher `compact` runs `hippo compact-resume` after Codex compacts a conversation, so the next prompt sends that block again; it restores a task snapshot only if one was saved with `hippo snapshot save` in the last 15 minutes, since Codex gets no `PreCompact` hook from hippo. Only the per-prompt hook has been seen working in a real Codex request; the compaction hook follows Codex's documented `compact` source. **Codex asks you to trust a new hook once:** open `/hooks` in Codex and trust both, or Codex skips them. Every install prints that reminder and `hippo doctor` repeats it, and warns when `hooks.json` is not valid JSON, since Codex then runs none of its hooks. hippo appends its two entries, keeps every other hook, never edits an entry already in the file (Codex treats a changed command as a new hook to trust), and leaves a file it cannot parse alone with a warning. Each hook carries a `commandWindows` form (`hippo.cmd ...`), because Codex runs hooks through PowerShell on Windows, where the execution policy can block npm's `hippo.ps1`. `hippo hook uninstall codex` removes only hippo's two exact commands, so a hook of yours in the same group, or one that runs another hippo command, stays.

### Changed

- **`HIPPO_SKIP_AUTO_INTEGRATIONS=1` now stops every agent file and hook `hippo init` writes.** It used to stop only the Codex wrapper repair in routine commands, so `hippo init` still patched `AGENTS.md` and `CLAUDE.md` and installed Claude Code's hooks with it set. Now `hippo init` and `hippo init --scan` leave instruction files, Claude Code's settings, the OpenCode plugin and Codex's `hooks.json` alone, as `--no-hooks` does. The daily run still follows `--no-schedule`.
- **`hippo hook install codex` works with no `codex` launcher on `PATH`.** It adds the memory hooks, says that session-end capture was not set up, and exits 0. It used to fail.
- **The docs say what the per-prompt hook sends.** The Claude Code and Codex hook sends your pinned memories plus the five most recent ones, and the Codex trust reminder says so; the README FAQ, the site's Claude Code and quickstart pages and the plugin description had said pinned memories only.
