### Fixed

- **`hippo serve` no longer dies silently on a listener error or an uncaught throw.** Once the port was bound the server had no `error` listener, so an accept failure such as running out of file descriptors became an uncaught exception and stopped the server for every caller with a bare stack trace. The listener now stays for the life of the server and logs `serve: listener error: ...`, and the server keeps answering. An uncaught exception or unhandled rejection in `hippo serve` now logs one `[hippo] error: serve uncaught exception: ...` line with the stack, drains requests already running through the same graceful stop a SIGTERM uses, removes the pidfile and exits 1 for the supervisor to restart it. `hippo mcp` and `hippo dashboard` share the same handlers; a dashboard port that is already in use now ends in one log line and exit 1.
