### Changed

- **A hippo root that holds an `other-store` file refuses every hippo.db open, from the CLI as from a request.** The file names the store that holds the folder's memories (for example `postgres`); an add-on writes it when it puts a folder on another store. Before this, a core command run on a server box, such as `hippo auth create`, could still create and write a hippo.db the served store never reads. Now it exits 1 with "This folder's memories live in the 'postgres' store, so hippo.db is not used here". An empty or unreadable marker refuses too. `withSqliteAllowed` waives the check, so a copy from the old hippo.db can still read it. `hippo audit repair` and the once-per-store quality repair in `hippo sleep`, which open hippo.db without `openHippoDb`, take the same check.
