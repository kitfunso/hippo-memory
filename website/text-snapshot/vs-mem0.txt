hippo vs memN
Both are open-source memory for AI agents, and they suit different jobs. memN uses a language model to extract memories, and memories stored through its hosted MCP server live in your MemN account. Hippo keeps memories in SQLite on your machine, needs no account and no model, and wires itself into the coding agents it finds.

What memN ships today
memN runs three ways, as a library, as a self-hosted server on Postgres, and as the hosted MemN platform. The open-source library needs a key for a language-model provider, OpenAI by default. Its MCP server is hosted and needs a MemN account and API key. On the hosted platform a background process marks an older memory superseded when a newer fact replaces it (memN docs (opens in new tab), checked N September N).
When to pick which
Pick hippo
Pick hippo when the memory is for coding agents on your machine, and you want no account, no API key and no model in the loop, with lessons you can mark wrong and files you can commit.
Pick memN
Pick memN when you are building an app whose memory belongs to your end users, the case memN describes as "customer support chatbots, AI assistants, and autonomous systems", or when its higher answer score matters more to you than running locally.

Is hippo an open-source memN alternative? +
Yes, if the memory is for coding agents on your own machine. Hippo is MIT-licensed, keeps memories in SQLite in your project and needs no account or API key. memN is Apache-N and runs as a library, a self-hosted server or a hosted platform.
