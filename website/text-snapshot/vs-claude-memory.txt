CLAUDE.md, auto memory and hippo: what goes where
Claude Code has two memories of its own, the CLAUDE.md files you write and the auto memory it writes. Hippo runs beside both. This page says what belongs in each, and what we measured when hippo was added.
Claude Code's two memories
CLAUDE.md files hold instructions you write, at managed, user, project and local level. Every file found is added to context, and none overrides another.
Auto memory holds notes Claude writes from your corrections and preferences, in a MEMORY.md index with one topic file per memory. It is on by default and stays on the machine. Each session loads the first N lines of MEMORY.md or the first NKB, whichever comes first.
Both are context, and neither is enforced. When two rules contradict each other, Claude may pick one arbitrarily (Claude Code's memory docs (opens in new tab), checked N November N).
What goes where
CLAUDE.md
Rules you write for every session, such as build commands and code style.
Auto memory
Leave this to Claude, which notes your corrections and preferences.
hippo
What comes up as you work, such as a failed command or a fact that changed. It is recalled when it matches the task and shared with your other agents.
Measured against built-in memory
Hippo runs beside Claude Code's own memory, so the fair test is built-in memory alone against built-in memory plus hippo on the same tasks. We ran it on N repositories, registered first.

Bringing CLAUDE.md notes into hippo
$ hippo import --claude CLAUDE.md --dry-run $ hippo import --claude CLAUDE.md The import skips hippo's own block and any duplicates. After that, hippo sleep at the end of each session also imports new auto memory notes, so they reach the store your other agents read.

Do I still need CLAUDE.md? +
Yes, for short standing rules such as build commands and code style. Claude Code's memory docs (opens in new tab) say that when two rules contradict each other, Claude may pick one arbitrarily. Hippo holds the lessons that pile up and recalls the ones that match the task.
