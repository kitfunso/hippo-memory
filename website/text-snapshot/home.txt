Your corrections, remembered by Claude Code, Codex and Cursor
Hippo is open-source memory that runs on your machine and gives the rules it captured back to the agent when a new session starts. In our Claude Code test on N repositories, adding it to built-in memory cut repeat mistakes from N in N to N at the same cost.

You have explained this before
You already keep a CLAUDE.md, and the agent keeps notes of its own. A new session can still repeat a mistake you corrected last week, and in our test Claude Code with its built-in memory did so N times in N
The same rule, every morning
You tell the agent "we use pnpm, never npm", and it runs pnpm add. The next day a new session runs npm install and leaves a package-lock.json beside your pnpm-lock.yaml. You type the same sentence again.
A correction buried in a transcript
The agent mocks the database in a test, you tell it this project tests against a real one, and it rewrites the test. The correction is still on disk, in a transcript no later session reads. The next session writes the mock again.
A CLAUDE.md nobody prunes
CLAUDE.md is the right place for build commands and code style. Six months on it also holds a note about a migration that finished in the spring and two rules that disagree. Claude Code's memory docs say that when two rules contradict each other, Claude may pick one arbitrarily.
The same failed command, again
The agent runs bare pytest, the run fails because this project needs uv run pytest, and two attempts later it has the right command. Next week a new session starts with bare pytest. The failure sits in last week's transcript, and nothing puts it in front of the agent before it types the command.

What hippo does between sessions
Hippo is a command-line tool, a set of agent hooks and a SQLite file in your project. The hooks do the routine work, and every memory they store is one you can read, correct or replace.
N What hippo keeps
When a Claude Code session ends, the SessionEnd hook checks your last N messages and the agent's last N against word patterns for decisions, rules, errors and preferences. A turn of yours with a rule word such as never, always or must is pinned as a rule, and a rule phrased another way can be missed. The PostToolUseFailure hook stores a failed tool call as an error memory, skipping interrupts, declined permissions and repeats. For anything the patterns missed, one command stores it by hand.
hippo remember "we use pnpm, never npm" --pin
N What the agent sees
In Claude Code, a SessionStart hook prints the rules hippo captured from you under the heading ## Rules from the user. On each prompt, the UserPromptSubmit hook adds your pinned memories and up to N memories that share words with the prompt, and it skips the pinned block when nothing in it has changed. In our test that prompt block came to about N tokens a session.
hippo recall "why did the deploy break" --why
N Correcting a memory
hippo outcome --bad weakens every memory from the last recall, so a memory that keeps misleading the agent sinks down the results. hippo supersede stores the new version of a fact and links the old one to it, and the old one leaves recall and stays on record. On a synthetic test where every mark was correct, a bad mark cut how often a wrong memory stayed in the top five from N% to N%, and real marks are noisier.
hippo supersede mem_aNbNcN "billing moved to bun"
N What fades
An ordinary memory has a N-day half-life, and each recall lengthens it by N days, so the memories your agent keeps recalling fade more slowly. An error memory starts at N days and a pinned memory never fades. hippo sleep moves a memory that has faded below the threshold to a dormant store, and hippo dormant restore <id> brings it back. On our short synthetic test decay made no measurable difference to recall.
N One command, six agents
hippo init creates a .hippo/ store in the project and sets up the agents it detects. Claude Code gets hooks for session start and end, each prompt, compaction and failed tool calls. Codex gets two hooks that run once you trust them in /hooks, Cursor and Pi read hippo's block in an existing AGENTS.md, and any MCP client can run hippo mcp for N memory tools. Installing the package alone captures nothing, and what runs after init depends on the agent.

How each part works
No language model writes your memories by default
MemN uses a language model to extract memories. Hippo's default capture matches word patterns, which costs nothing to run and misses rules phrased in other ways. Storing the LoCoMo test conversations took MemN N language-model calls and hippo none.
Stored without a model call
A memory is a row in SQLite, written by word patterns, hooks and the command line. Search is BMN keyword ranking out of the box, with no model and no network call, and a local embedder is an optional install. On the same LoCoMo test MemN's answers scored N% and hippo's N%, a comparison of the two whole systems.
Files you can read and commit
The store is .hippo/hippo.db in each project, with a global store in ~/.hippo/. Hippo writes a markdown mirror after each change, so a memory can be read, found with grep and reviewed in a pull request. hippo recall --why shows which words matched for each memory it returns.
Local, with a named list of exceptions
Hippo needs no account and no API key, and recall makes no network call by default. Text goes to an outside provider only through an API embedder, an API reranker, hippo refine, model-read rule capture, or hippo sleep when ANTHROPIC_API_KEY is set. The first four are off until you turn them on, and {"extraction":{"enabled":false}} in .hippo/config.json switches the last one off.
One store behind every agent
Claude Code, Codex and Cursor read the same .hippo/ store in a project, so what one agent was told is there for the others. Hippo also imports the notes that Claude Code, Codex, Gemini CLI and three other tools keep for themselves, and the import never changes those notes. The memory text it adds to a prompt is paid for as input tokens, and in our test the arm with hippo cost the same as the arm without, a ratio of N

For a team that runs more than one agent
Your developers use different agents, and each agent keeps its own notes in its own format. Hippo gives the agents on each machine one store, in files your team can read.
The commercial edition is planned; its private repository is a scaffold, not a released enterprise product.
What teams can run today
The same rules for every agent
On a developer's machine, Claude Code, Codex and Cursor read the same .hippo/ store in the project. Commit the markdown mirrors and the rules your agents work to can be reviewed beside the code. Slack and GitHub connectors bring in what the team has already written down.
What you can run today
The MIT core includes an HTTP server with tenants, API keys, admin and member roles, per-key scope grants and an audit log on every change. Keys are stored scrypt-hashed, and one API call deletes a memory. SSO, SCIM, SIEM export, a hosted service and an SLA are on the plan for the commercial edition, and none of it is released.
A pilot measured on your work
We have no team result to show. The fair test is a holdout, where a random share of sessions runs without memory and you compare cost per merged PR and repeat errors between the two groups. Hippo's holdout withholds memories from the hooks, while hippo recall and the MCP tools stay open, so a pilot has to account for those. Open a pilot request with your team size and the agents you use.
Stored on your machine, and what can leave it
Memories live in SQLite, in .hippo/hippo.db in each project and a global store in ~/.hippo/, with markdown mirrors you can read, grep and commit. The package has zero runtime dependencies. Recall makes no network call by default. Text leaves your machine only if you turn on an API embedder, a reranker or model-read rule capture, run hippo refine, or have ANTHROPIC_API_KEY set when hippo sleep runs, and one config line switches that last one off.
Who should use something else
Hippo is for coding agents on machines you control. MemN fits better when the memory belongs to your app's end users, Zep when you want a managed knowledge graph built from business data, and Letta Code when you want an agent that edits its own memory.

Do I still need CLAUDE.md? +
Yes, for short standing rules such as build commands and code style. Claude Code's memory docs (opens in new tab) say that when two rules contradict each other, Claude may pick one arbitrarily. Hippo holds the lessons that pile up and recalls the ones that match the task.
What does hippo cost? +
Nothing. Hippo is MIT-licensed and needs no account or API key. Optional features that call an outside provider bill through it. The Jev reranker costs about N USD a recall, and API embedders and sleep's fact extraction use your own keys.
Try it on the repository you have open
hippo init creates the project's store, sets up the agents it detects and schedules a daily N:Nam run, and --no-hooks and --no-schedule skip those parts. hippo doctor checks Node, the store and the agent hooks, and each problem it finds names its fix. If hippo misses a rule you expected it to keep, open an issue with an example.
