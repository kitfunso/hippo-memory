hippo vs claude-mem
Both capture coding-agent sessions locally into SQLite and connect across Claude Code, Codex, Cursor and MCP. claude-mem runs a persistent Bun worker daemon that sends tool executions through an observer language model to compress them into a session timeline. Hippo runs with zero background daemon, zero runtime dependencies and zero language-model calls on save or recall, writing git-readable markdown mirrors beside SQLite.
Zero LLM spend vs background observer calls
claude-mem hooks into PostToolUse and Stop events, forwarding tool activity to a local Bun worker that runs an observer model (defaulting to Haiku on your plan, an API key, Ollama or hosted tokens) to summarise observations into SQLite and optional Chroma (claude-mem worker docs (opens in new tab), checked N November N).
Hippo saves rules, failed commands and project lessons with zero extra model calls and zero telemetry. Every memory lives in .hippo/ as SQLite plus a plain markdown mirror you can grep, diff and review in a pull request. When a recalled memory leads to a bad answer, hippo outcome --bad pushes it down, and hippo supersede replaces stale facts cleanly.

When to pick which
Pick hippo
Pick hippo when you want zero extra LLM calls, zero background daemon, MIT code with zero runtime dependencies, git-reviewable markdown rules and outcome-based ranking that cuts repeat mistakes in half.
Pick claude-mem
Pick claude-mem when you want an always-on observer model compressing every tool execution into a searchable chronological timeline with a live web viewer, and extra model calls fit your workflow.

Why pick hippo over claude-mem? +
Pick hippo if you want zero background LLM spend, zero daemon processes and plain markdown mirrors you can review in git pull requests. Hippo also ranks memories by outcome via hippo outcome --bad, supersedes outdated facts and cut repeat mistakes from N in N to N in N across N repositories at the same token cost.
Does hippo need an Anthropic API key or extra model calls like claude-mem? +
No. Saving, capturing rules and errors, and recalling memories in hippo make zero language-model calls and need no API key or cloud account.
