hippo vs Letta
Letta, formerly MemGPT, now builds Letta Code, an agent harness whose memory lives in blocks the agent edits itself. Hippo is memory for the agents you already run, such as Claude Code, Codex and Cursor, in one store they share. So the choice is mostly about whether you want to switch agents.
Who edits the memory
Both keep memory where you can see it. Letta Code tracks its context in git, and hippo writes markdown mirrors you can commit. In Letta the agent rewrites its own memory blocks with built-in tools. In hippo, memories come from hooks, the CLI and MCP tools, and you can mark a recalled one wrong or replace an old fact.

What Letta ships today
Letta Code is Apache-N and you connect your own model keys. Without signing in your agents are stored on local disk, and /login backs them up to Letta's cloud. The original Letta server, the MemGPT line, is retired to an archive branch (Letta's pages (opens in new tab), checked N September N).
When to pick which
Pick hippo
Pick hippo when you already use Claude Code, Codex or Cursor and want them to share one store of lessons you can correct, on your machine with no account.
Pick Letta
Pick Letta when you want a coding agent whose memory is part of the agent, and you are ready to switch agents to get it.
