hippo vs Supermemory
Supermemory is a cloud-first memory and RAG API with open-source coding-agent plugins. Its core memory engine and downloadable local binary are closed-source, its MCP server is Platform-only, and every save runs through an LLM. Hippo is N% MIT open source, runs locally with zero runtime dependencies and zero LLM calls on save, includes a local MCP server and keeps readable markdown copies you can commit to git.
Open local infrastructure vs closed engine and metered tokens
Supermemory's self-hosting docs note that supermemory local is a closed-source binary capped at N stored documents under a lite licence, saves data as an encrypted snapshot file (~/.supermemory/data), requires an external LLM provider key or local model server to extract memories, and excludes MCP and external connectors (Supermemory self-hosting docs (opens in new tab), pricing (opens in new tab), checked N November N).
Hippo gives you full ownership of both the engine and the files. There is no document limit, no account, no per-token charge and no telemetry. Local MCP (hippo mcp, N tools) ships in the MIT package, every memory has a plain markdown mirror in .hippo/, and bad recalls can be weakened directly with hippo outcome --bad.

Is Supermemory open source like hippo? +
Only Supermemory plugins, SDKs and repo tooling are open source. Per Supermemory self-hosting docs (checked N November N), the memory engine and downloadable supermemory local binary are closed-source, capped at N documents and exclude MCP. Hippo is N% MIT open source with local MCP and no document limit.
Can I run hippo completely offline with no cloud account or API key? +
Yes. Hippo stores everything locally in SQLite and markdown inside your repository, runs recall and rule capture with zero LLM calls and never requires a cloud account or metered token billing.
