Retrieval scores say whether the right memory comes back. This test asks what the agent then does. Each run teaches Claude Code one rule by correcting it, then gives it later tasks where the same mistake is possible, with and without hippo.

Standard task: per-question haystack
Each question ships its own haystack of about N conversation sessions, and the job is to retrieve the session that holds the answer. This is the standard LongMemEval-S setup, the same one published systems report. Recall at N on the _s split:
Embedder R@N R@N R@N
MiniLM-LN (local, optional install) N N N
voyage-N-large (opt-in, June N) N N N
These scores count a hit when any answer session is in the top N over all N questions. hippo reaches N% that way with a free local embedder, the best of five settings in its benchmark scripts. The June N build scored N%, and the re-measure (opens in new tab) shows both runs.
The stricter measure counts a hit only when every answer session is in the top N over the N questions that have an answer. The same runs score N to N% there. gbrain first published N%, an any-session score, and its report (opens in new tab) now leads with the strict one: N% (N of N) with the paid Voyage rerank-N reranker, N% without it. On strict recall gbrain is ahead. Any-session recall is near its ceiling on this task; strict recall is not.
Large store: one unified memory
Point retrieval at a single store of all N sessions, with no pre-scoped haystack, closer to how an agent's memory actually accumulates. Recall stops being free (measured June N):
N R@N · MiniLM-LN (local, optional install)
N R@N · voyage-N-large (opt-in)
A stronger embedder helps here (N to N) but neither is usable on its own: the answer drowns among thousands of distractors. This is where we expect the memory lifecycle to matter, and measuring it is the next benchmark on the roadmap. It is not shown yet: on our tests so far, decay made no measurable difference and sleep cost recall.
Reranking: what a paid model bought, and what it did not
hippo recall "<query>" --reranker jev sends the top N candidates to the hosted TypeSafe Jev (opens in new tab) API and reorders them. It is off by default and the default recall path makes no network call. Ranking on a private N-query developer store, so unlike the two benchmarks above this one is not redistributable and you cannot rerun it. All figures aggregated over N-draw paired bootstrap runs, with N% intervals:
Metric Base Cross-encoder Jev Jev minus cross-encoder
R@N N N N +N [N N]
R@N N N N +N [N N]
MRR N N N +N [N N]

The R@N margin held in N of N bootstrap seeds, and a permutation null with arm labels shuffled inside each query reached it in N of N runs. The R@N margin replicated on LongMemEval at n=N +N [N N]; R@N tied there. Cost is about N USD a recall, pN N ms over N calls.
What it did not do
Better ranking did not produce better answers. Three graded-answer tests on LongMemEval all tied against the free local cross-encoder, and those three share one N-question set, so they are not three independent tries. What Jev buys today is a shorter context: N Jev-ranked memories answer as well as N ranked by the cross-encoder, roughly N fewer tokens a query. Turning it on also sends your query and candidate memory text to a third party.

Reproduce it
The data is longmemeval_s_cleaned.json (SHA-N dNfNeaN), N questions over N sessions. Retrieval is turn-level dense plus BMN fused with reciprocal rank fusion and max-pooled to session, by the scripts in benchmarks/longmemeval rather than hippo recall. Embeddings are LN-normalized; the local embedder is MiniLM (an optional install), with an opt-in pluggable provider for frontier embedders.
Every measurement hippo has published, pre-registrations kept next to their results, is indexed in docs/evals (opens in new tab). That index includes the runs that failed and the one claim we retracted.

LoCoMo: conversational evidence recall
LoCoMo (opens in new tab) is N long multi-session conversations, N turns and N questions. hippo scores it deterministically: did the gold evidence turn land in the top N recalled memories? No LLM judge. Measured once on vN (N-N-N) with MiniLM-LN the default embedder then and an optional install since N:
Category n Evidence R@N
single-hop N N
multi-hop N N
temporal-reasoning N N
open-domain N N
adversarial N N
overall N N
A point estimate, not an exact value: n=N and the run predates the vN determinism fix and a harness fix that lost tags on N% of stored rows. Not comparable to the LLM-as-judge numbers MemN and Letta publish. Informational only, gates no feature. Protocol, caveats and regeneration commands: LOCOMO_INVESTIGATION.md (opens in new tab).
