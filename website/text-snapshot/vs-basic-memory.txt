hippo vs Basic Memory
Both are local-first memory tools that work across Claude Code, Codex and Cursor with zero language-model calls on save. Basic Memory is an AGPL-N Python knowledge base built around Obsidian-style markdown notes that you or the agent author explicitly. Hippo is MIT-licensed with zero runtime dependencies, automatic rule and tool-failure capture, outcome tracking and fact supersession.
Authored notes vs outcome-ranked coding memory
In Basic Memory, notes sit in a markdown folder with wikilinks and YAML frontmatter, indexed by SQLite and FastEmbed so humans and agents share a wiki. Every note keeps equal standing unless someone edits it by hand.
Hippo is built for coding agents that repeat mistakes across sessions. It captures stated rules and failed tool calls, strengthens memories that get recalled, weakens memories behind a bad answer with hippo outcome --bad, and retires outdated facts with hippo supersede while keeping readable markdown mirrors in .hippo/.

What Basic Memory ships today
Basic Memory is released under AGPL-N and runs on Python N+ via uv, storing plain markdown files indexed in SQLite with sqlite-vec (or optional Postgres/Milvus). It connects to Claude Code, Codex and Cursor over MCP and provides bm install hooks for Claude Code and Codex. How does hippo differ from Basic Memory for coding agents? +
Both run locally with markdown files, SQLite and zero LLM calls on save. Basic Memory is an AGPL-N Python knowledge base where you or the agent author Obsidian-style notes. Hippo is MIT with zero runtime dependencies on Node.js, captures coding rules and tool failures from sessions, weakens wrong memories via hippo outcome --bad, supersedes stale facts and ships with pre-registered repeat-mistake results.
Can I switch from Basic Memory to hippo without losing my notes? +
Yes. Basic Memory stores plain markdown files on disk, and hippo imports markdown folders directly while keeping your existing files untouched.
