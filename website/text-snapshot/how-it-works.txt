How hippo decides what your agent remembers
Every memory has a strength. It fades on a half-life, grows each time the memory is recalled, and drops when you mark it wrong. The hippocampus inspired the design, and we tested each part on its own. On synthetic tests, outcome marks and recall strengthening helped and decay made no measurable difference. Sleep lowered recall on one scorer, and the rest is unmeasured.

Marking a recall good or bad
hippo outcome --good or --bad marks the memories from the last recall. After N good marks and no bad ones, a memory's half-life is about N% longer. After N bad marks and no good ones it decays N times as fast. On a synthetic test where every mark was correct, a bad mark cut how often a wrong memory stayed in the top five from N% to N%. Real marks are noisier, because --bad marks the whole recall batch.
Recall makes a memory last longer
Each recall adds N days to a memory's half-life, so N days becomes N and then N Recall ranks memories by relevance, strength and recency, and the strongest matches fill the token budget first. In the first round of our audit this helped on the synthetic test, in its best case.
Errors last twice as long
A memory stored with --error, or captured from a failed tool call, gets a N-day half-life against the usual N We haven't measured whether that helps.
Decay, on a N-day half-life
A memory's strength halves each time a half-life passes without use. The default used to be N days, which turned out to be a bug. On a test we registered first, the current version of a fact was in the top five N% of the time at N days and N% at N We did not tune N It tied with N days and with decay switched off, so on that test decay made no measurable difference. Set defaultHalfLifeDays in .hippo/config.json to choose your own, or pin a memory so it never decays.
Sleep merges related memories
hippo sleep merges two or more related episodes into one pattern, and the originals fade. It keeps the store tidy. It has not been shown to improve recall, and on one scorer a slept store scored N points lower than the same store never slept. A memory that fades below the threshold goes dormant, hippo dormant restore <id> brings it back, and a dormant memory nobody restores is deleted after N days by default.
Replacing a fact, and spotting contradictions
hippo supersede <id> "<new fact>" stores the new version and links the old one to it. The old one leaves recall and stays on record, and hippo recall --as-of <date> shows what was current on a given day. hippo reject <id> --reason "<why>" stops a value coming back at all. When two memories overlap in content and contradict each other, hippo records a conflict that hippo conflicts lists. Each memory also carries a confidence level of verified, observed, inferred or stale. None of this is measured yet.

Is this just RAG? +
Partly. Recall is search, BMN plus embeddings if you install them. The difference is that the store changes as your agent works. A memory you mark wrong drops down the results, a newer fact replaces an old one, and unused memories fade.
