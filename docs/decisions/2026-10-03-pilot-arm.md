# Pilot arm rows in the token ledger

Date: 2026-10-03
Status: accepted
Links: ROADMAP.md CD11, CD12; hippo-enterprise docs/decisions/2026-10-03-pilot-report.md (reader src/pilot/store.ts)

## Context
The enterprise pilot report needs one arm per session. It reads `token_ledger` rows with `surface='pilot'`,
`event='arm'`, `block_hash` `hippo` or `holdout`, `items` = holdout rate in basis points, `tokens=0`.
It marks as conflict: holdout at rate 0, hippo at 10000, a non-integer rate, more than one arm, rate or tenant per session.

## Decision
- `pilot.holdoutRateBp` in config, integer 0..10000, read from the ledger store root. Default 0 means no lookup, no row, no holdout. A bad value warns and is 0.
- The arm is `holdout` when `sha256(sessionId)` first 8 hex digits, mod 10000, is below the rate (`src/pilot-arm.ts`).
- `hippo context` books the row at the first call that carries a payload session id, before the budget and nothing-to-inject returns, with or without `--pinned-only`. Writes use `BEGIN IMMEDIATE` with a 1 s wait. The lookup has no tenant filter. On any error the hash arm is used and no row is written.
- Env-only session ids and sub-agent payloads read the stored arm, else the hash; they write nothing. `compact-resume` only reads.
- A holdout reuses `disabled()` of the delivery recorder, the same state as `--budget 0`.
- Arm rows are pruned with the ledger's 90 days. A session resumed after that may get a second row.
- Setting the rate to 0 ends every holdout at once; do it only after the pilot window closes.
- Readers that skip arm rows: `summarizeTokenUse`, `tokensBySession`. `pilot` is in no surface list.

## Not suppressed
Capture hooks, the pre-compact summariser request, `last-sleep`, and true pulls (`hippo recall`, HTTP API). OpenCode, OpenClaw and pi have no session payload and stay unassigned.

## Known leak channels
- Cross-store: with no local store the hook writes the arm to the global store. A later `hippo context` in a subfolder with its own local `.hippo` finds no row there and uses that store's config and the hash. A pilot must collect every store.
- MCP: `hippo_context` calls `api.getContext` with no session id. It is an unrecorded pull that the report cannot flag.
- Env: `CLAUDE_CODE_SESSION_ID` reaches the agent's Bash tool, so the env-only read path covers the pull the CLAUDE.md block tells the agent to make.

## Reconsider when
A host sends a session id to MCP, or the report needs arms for sessions without a payload id.
