How Claude Code saves memories, and what hippo can take from it

2026-09-28. Hippo side read from the source at origin/master 8a00c7b; Claude Code side from the official memory docs and the memory instructions Claude Code gives the model.

The short version: Claude Code spends its effort at write time. The model decides what's worth keeping, writes it in a fixed shape with the reason attached, and updates the old entry instead of adding a new one. Hippo spends its effort after the fact. It captures a lot by regex and git, then decays, dedupes, merges and flags conflicts during sleep. Hippo's machinery is stronger. Claude Code's individual memories are better. Track Z (zero-touch) needs both.

What hippo can learn, ranked by value for Track Z

  1. Store the reason with the rule. Add why and apply fields, and have capture fill them from the turn where the correction happened. Why: a rule with its reason lets the agent handle the edge case instead of applying the rule blindly. Today a captured "never X" arrives without context in a session months later. How: add two nullable columns and have remember --why --apply set them. Capture's "rule" and "decision" categories take the surrounding user sentence as why. Render as rule — Why: … in injection. Cost: a schema migration on live stores, so it needs a migration plan and sign-off.
  2. Decide update or create at write time. Before inserting, find the closest existing memory. If it covers the same thing, supersede it with the merged text instead of adding a row. Why: sleep's concatenation merge produces "[Consolidated from 2 related memories]" blobs (visible in tonight's sleep log). Claude Code's rule, one fact per entry and update in place, keeps the store readable and the injection budget spent on distinct facts. How: remember and capture call recall with a top-1 threshold. Above it, supersede with a replacement: LLM-written when a key is set, else new text wins. Keep the sleep merge as a backstop only.
  3. Inject an index, not just pinned and recent. Add one line per high-strength memory (id plus a ~12-word hook) under the pinned block, with hippo show <id> to expand. Why: today the agent can't know what hippo knows unless it happens to search for it. Claude Code's 200-line index is why its memory feels present without prompt-relevant recall. How: store a description per memory (the first sentence, or LLM-written at sleep) and render the top N by strength and scope into the existing budget.
  4. Write down what not to save, and stop saving what git already knows. Put Claude Code's exclusion list into the hook text and the hippo_remember tool description. Default autoLearnOnSleep to keep only commits whose body explains a cause, not bare subjects. Why: commit subjects are derivable from git log. They crowd out lessons, and they're a big share of the "low-quality" rows the audit keeps flagging (35 tonight).
  5. Tell the agent to verify at recall. Add one line to the injected block: "Memories are point-in-time; if one names a file, function or flag, check it exists before acting on it." Why: the labels ("Previously observed") say a memory is old, but not what to do about it. This is the cheapest change on the list: text only, no schema.
  6. Read edited mirrors back. On sleep, if a mirror file's hash differs from what was written, treat the file as a user edit and supersede the row. Why: users trust files they can open and fix. Today fixing a mirror silently does nothing, which is worse than having no mirror at all.
  7. Keep the frontmatter when importing Claude Code memories. learnFromMemoryMd takes the body only and cuts it at 1,500 characters (cli.ts:3003). Map type to tags, description to the hook, and the Why/How lines to the fields in point 1. Why: these are the best-shaped memories hippo ever receives, and the import currently flattens them into anonymous "observed" text.

What hippo should not copy

Claude Code has no decay, no search, no conflict detection and a hard 200-line index cap. It works because the model curates a small set by hand. Hippo's promise is memory without that curation. So take the write-time shape (reason, type, one fact, update in place), not the small-and-manual model.
