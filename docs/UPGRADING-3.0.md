# Upgrading to 3.0

hippo 3.0 removes names that 2.1 marked `@deprecated` and the raw store functions from the package root, and a store you build on `hippo-memory/store-kit` must set the groups recall, remember and context run on. A `MemoryEntry` now names its fields in camelCase; [MemoryEntry field names](#memoryentry-field-names) lists each one. Nothing else changes: hippo.db keeps its columns, and files on disk keep their format. Export JSON, HTTP and MCP answers keep their shape.

| Removed in 3.0 | Use instead |
| --- | --- |
| `openHippoDb`, `openHippoDbReadOnly`, `closeHippoDb` and the `DatabaseSyncLike` type on the package root. | `sqliteStore(hippoRoot)` from `hippo-memory/store-kit`. No package entry hands out a raw SQLite handle. A script that loads `dist/db/index.js` by path still gets `openHippoDb` and `openHippoDbReadOnly`: each is now an unscoped connection of its own, with no store runtime, request session or worker fence, and `openHippoDb(root, { busyWaitMs })` no longer takes a `grant`. Only the SQLite adapter mints a `DbGrant`. |
| The snake_case option keys of `createMemory`: `emotional_valence`, `schema_fit`, `trace_outcome`, `source_session_id`, `valid_from`, `extracted_from`, `dag_level`, `dag_parent_id` and `artifact_ref`. | The camelCase keys 2.1 added: `emotionalValence`, `schemaFit`, `traceOutcome`, `sourceSessionId`, `validFrom`, `extractedFrom`, `dagLevel`, `dagParentId` and `artifactRef`. A snake_case key is now a type error and is ignored at run time. The entry that comes back names its fields in camelCase too (next row). |
| The snake_case field names of `MemoryEntry`, such as `entry.tenant_id`, `entry.last_retrieved` and `entry.superseded_by`. | The camelCase names in [MemoryEntry field names](#memoryentry-field-names), such as `entry.tenantId`. Files and wire formats keep their snake_case keys: `hippo export`, the markdown mirrors, dormant snapshots, `hippo trace --json`, `hippo recall --json` and the HTTP and MCP answers read as before. A store write of an entry with `tenant_id` and no `tenantId` throws `TypeError: tenant_id was renamed to tenantId in 3.0`, so a 2.x caller's row cannot land in the default tenant. An eval script that reads snake_case keys can import the `*Wire` forms from `hippo-memory/testing`, such as `loadAllEntriesWire`; they take and return `MemoryWire`, the snake_case shape. Store-kit shapes built from an entry follow it: `descendantAdmits` reads `originProject`, the patch a store's `consolidation.applyRebuild` gets names `descendantCount`, `earliestAt` and `latestAt`, and `consolidation.childrenOfSummaries` and the `sharing` text keys carry `tenantId`. |
| `MemoryEntry.bm25_score`: the raw FTS5 `bm25()` rank a row from a store search carried, such as a row `loadRecallSearchEntries` on `hippo-memory/testing` answers. | Nothing replaces it on the row: the rank still orders those rows, and no row carries it. A hit's score is on `SearchResult`, from `search` and `hybridSearch` on `hippo-memory/search`: `score`, and `bm25`, which hippo's own BM25 scorer gives on a different scale from FTS5. `MemoryWire` keeps the optional `bm25_score` key, so a 2.x wire object still type-checks; 3.0 never writes or reads it. |
| The snake_case field names of `MemoryConflict` from `hippo-memory/store-kit`: `memory_a_id`, `memory_b_id`, `detected_at` and `updated_at`. | `memoryAId`, `memoryBId`, `detectedAt` and `updatedAt`; `id`, `reason`, `score` and `status` keep their names. A store you build returns conflicts with the camelCase names from `conflicts.list` and `conflicts.get`. Files and wire formats keep their snake_case keys: `hippo conflicts --json`, the `open_conflicts` of `hippo trace --json` and the conflict markdown mirrors print as before. |
| The snake_case fields of `HippoConfig['physics']`, such as `config.physics.G_query`. | The camelCase names `gQuery`, `gMemory`, `kRepulsion`, `interferenceGain`, `momentumWeight`, `maxVelocity`, `feedbackAlpha`, `temperatureDecay`, `clusterThreshold` and `clusterTopK`. A `config.json` keeps its keys, so `"physics": { "G_query": 3 }` still sets `gQuery`. `hippo support-bundle` shows the effective config under the new names. |
| `physicsSearch` on the package root. | `physicsSearch` from `hippo-memory/store-kit`, with the same signature. To rank recall by physics without calling it, set `physics.enabled` to `'auto'` or `true` in config. |
| `import { search, hybridSearch, multihopSearch } from 'hippo-memory'`, and the other search names on the package root: `explainMatch`, `MatchExplanation`, `detectTemporalDirection`, `temporalBoost`, `computeTemporalRange`, `SearchResult`, `graphExpandRecall`, `MAX_HOPS`, `DEFAULT_MAX_NEIGHBORS` and `GraphExpandOpts`. | `import { search, hybridSearch, multihopSearch } from 'hippo-memory/search'`. The signatures do not change. `tokenize`, `textOverlap`, `isEmbeddingAvailable` and `getEmbedding` stay on the package root. |
| `import { importMarkdown } from 'hippo-memory'`, and the other importer names on the package root: `importChatGPT`, `importClaude`, `importCursor`, `importGenericFile`, `importVault`, `importEntries`, `ImportResult` and `ImportOptions`. | `import { importMarkdown } from 'hippo-memory/importers'`. The signatures do not change. |
| `import { runFeatureEval } from 'hippo-memory'`, and the other eval-suite names on the package root: `formatResult`, `resultToBaseline`, `detectRegressions` and `buildSyntheticCorpus`. | `import { runFeatureEval } from 'hippo-memory/eval'`. The signatures do not change. |
| A `HippoStore` could leave any store group unset, and each route or MCP tool that named a missing group answered 501. | Set the four required groups, `keyWrites`, `entryWrites`, `contextReads` and `auditLog`, and the base methods beside them: `RequiredStore` from `hippo-memory/store-kit` is the smallest store, and a store without one of them is a type error. Every group `OPTIONAL_GROUPS` lists may stay unset, among them `vectors`, `vectorWrites`, `dagReads`, `graphReads`, `sessions`, `goals` and `reports`, which 2.x required. Without `vectors` recall ranks by BM25 alone, `physics` mode included, and `GET /v1/vectors/nearest` answers 501; without `graphReads` recall expands no graph and the graph view answers 501; without `dagReads` drill and assemble answer 501; without `reports` status and the report verbs answer 501 and no write starts an auto-sleep; without `sessions` or `goals` their verbs and entries refuse. Each HTTP route, MCP tool and CLI verb that needs a group checks for it once at start, and on a store without it answers 501 `store_not_ported`, or `hippo` exits 1 with the same message. A store that serves only some groups can spread `sqliteStore(hippoRoot)` and replace the groups it serves: under `serve()` the rest reach a fenced hippo.db and answer 501 `store_not_ported`, as before. |
| `narrowStore`, `StoreWith<G>` and `ContextWith<G>` from `hippo-memory/store-kit`. | `HippoStore` in place of `StoreWith<G>`. Drop each `narrowStore` call: every required group is already set. To reach an entry that names an optional group, narrow the store and hand the entry a `Context` built around it: `const { store } = ctx; if (hasGroup(store, 'sessions')) await bindSessionOwner({ ...ctx, store }, sessionId);`. Narrowing `ctx.store` in place does not narrow `ctx`, so passing `ctx` itself stays a type error; or call `requireGroup(store, group)`, which returns the group or throws `StoreNotPortedError`, a 501. Never rebuild the store itself as a spread such as `{ ...store, sessions: requireGroup(store, 'sessions') }`: the copy drops the store's own non-enumerable marks, so a request no longer reopens it on its session and a worker store stops answering off the server thread. |
| `Context.store` was optional, and an entry handed a `Context` without one opened hippo.db under `hippoRoot`: `sleep` on the package root, and `authCreate`, `authCreateSelf`, `authRevoke` and `promptHookContext` on `hippo-memory/server`. | `Context.store` is required. Build the store once and put it on the `Context`, for example `store: sqliteStore(hippoRoot)` from `hippo-memory/store-kit`; a `Context` without `store` is a type error and fails at run time. |
| `Context.store` was a `HippoStore`, which named every store group. | `Context.store` is a `RequiredStore`. An entry that reads an optional group names it in its parameter type: narrow the store and hand the entry a `Context` built around it: `const { store } = ctx; if (hasGroup(store, 'sessions')) await bindSessionOwner({ ...ctx, store }, sessionId);`. Narrowing `ctx.store` in place does not narrow `ctx`, so passing `ctx` itself stays a type error. A `Context` whose `reach` names no ledger home (`ContextReach.ledger`, a `LedgerHome`, which a root sets on a store that keeps a ledger) books no session-end re-reads on its own store's ledger; a 2.x `Context` with no reach booked them. |
| `reports.entriesWhere(filter, page)` on the `reports` group of `hippo-memory/store-kit`. | The base method `entriesWhere(filter, page)`, beside `entriesByIds`, with the same `EntryFilter` and `PageRequest`. A store moves the method off its `reports` group, and the `Reports` type on `hippo-memory/store-kit` no longer has it. |
| `Context.callers.autoSleep` on `hippo-memory/server` held `run`, `hostTenantId` and its latch, and a write counted the rows since the last sleep through `ctx.store.reports`. | It also holds `newSince(tenantId, now)`, which a root binds on a store that keeps `reports`, for example with the request's own store; a write calls it and reads no group of its own. A host with no `newSince` starts no auto-sleep. |
| `bindSessionOwner`, `compactResumeForCaller`, `sessionEndHandoffForCaller`, `preCompactForCaller`, `saveCompactionItemsForCaller` and `captureFailureForCaller` on `hippo-memory/server` took a `Context` whose store held `sessions`. | Their parameter type names `sessions`: `EntryContext<ContextWith<'sessions'>>`, with `compactions`, or `failureLog` and `lessonWrites`, beside it on the last three. A `Context` without `sessions` is a type error: narrow the store and hand the entry a `Context` built around it: `const { store } = ctx; if (hasGroup(store, 'sessions')) await bindSessionOwner({ ...ctx, store }, sessionId);`. Narrowing `ctx.store` in place does not narrow `ctx`, so passing `ctx` itself stays a type error. |
| `goalPush(ctx, opts)` and `folderIndex(folder)` in `dist/entry/eval-scripts.js`, the module the repo's eval scripts import (not a package export): `goalPush` took any `Context`. | Its store must hold `goals`: the parameter is `EntryContext<ContextWith<'goals'>>`. `folderIndex(folder)` answers `undefined` only for a store with neither `embeddingIndex` nor both `vectors` and `vectorWrites`. |
| `initStore(hippoRoot, opts?)` on `hippo-memory/testing`, whose `opts` held a `grant`. | `opts` is `{ runtime?, session?, busyWaitMs? }`, as `sqliteStore` takes. `initStore(hippoRoot)` reads as before. |
| `VectorSource`, the `source` option of `hybridSearch` on `hippo-memory/search`, held `store` (a `HippoStore`), `provider` and `onHippoDb`. | `store` is a `RequiredStore`, and the source also holds the store's `vectors` group, which it needs, and its `graphReads` when the store keeps one. Narrow the store first: `if (hasGroup(store, 'vectors')) { await hybridSearch(query, entries, { source: { store, vectors: store.vectors, graphReads: hasGroup(store, 'graphReads') ? store.graphReads : undefined, provider } }); }`. A store without `vectors` has no source; leave `source` unset and the ranking is BM25 alone. The `store` option of `hybridSearch`, and of `physicsSearch` on `hippo-memory/store-kit`, takes any store and reads its `vectors` and `graphReads` when set. |
| `SleepGroup` named the `SleepGroups` groups and `objects`; `SleepStore` and `SleepContext` on the package root, and `ConsolidationStore`, got `vectors` and `graphReads` from `HippoStore`, which required them. | `SleepGroup` also names `graphReads` and `vectors`, now optional on `HippoStore`, so `SleepStore` and `SleepContext` require both, and `ConsolidationStore` requires `vectors`: sleep moves the physics particles through `vectors` and rebuilds the graph against `graphReads`. A store typed to the 2.x `SleepStore` already has both. A store without them cannot sleep: set them, or spread `sqliteStore(hippoRoot)` and replace the groups it serves, as in `const sleeper: SleepStore = { ...sqliteStore(hippoRoot), consolidation };`. |
| The `store` option of `hybridSearch` and `physicsSearch`, and of `hybridSearchWire` on `hippo-memory/testing`, took a `HippoStore`. | Each takes any store and reads its `vectors` and `graphReads` when set. `physicsSearch` with no `hippoRoot`, or on a store without `vectors`, ranks the rows by BM25 through `hybridSearch`, where 2.x answered no rows. |
| `VectorWrites` on `hippo-memory/store-kit` had `entriesWithoutVector` and `writeVectors`. | Add `indexKey()`, which answers one string per vector index: every `vectorWrites` group that writes one index answers the same key, so two embed runs on it take turns whatever store object each holds. `sqliteStore` answers the index's lock key. |

| `RequestStores`, the type of `initStore`'s `opts.session`, had `get(root)` and `getWithFacts(root)`, which opened hippo.db on the session with no grant. | Both are gone: only the SQLite adapter opens a session's handle, through its grant. A script that needs a handle of its own loads `openHippoDb` from `dist/db/index.js` by path, as the row on `openHippoDb` above says. |
