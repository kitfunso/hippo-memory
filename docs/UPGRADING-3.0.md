# Upgrading to 3.0

hippo 3.0 removes names that 2.1 marked `@deprecated` and the raw store functions from the package root, and a store you build on `hippo-memory/store-kit` must set every store group but four. Nothing else changes: an entry keeps its field names, hippo.db keeps its columns and files on disk keep their format. HTTP and MCP answers keep their shape.

| Removed in 3.0 | Use instead |
| --- | --- |
| `openHippoDb`, `openHippoDbReadOnly`, `closeHippoDb` and the `DatabaseSyncLike` type on the package root. | `sqliteStore(hippoRoot)` from `hippo-memory/store-kit`. No package entry hands out a raw SQLite handle. |
| The snake_case option keys of `createMemory`: `emotional_valence`, `schema_fit`, `trace_outcome`, `source_session_id`, `valid_from`, `extracted_from`, `dag_level`, `dag_parent_id` and `artifact_ref`. | The camelCase keys 2.1 added: `emotionalValence`, `schemaFit`, `traceOutcome`, `sourceSessionId`, `validFrom`, `extractedFrom`, `dagLevel`, `dagParentId` and `artifactRef`. A snake_case key is now a type error and is ignored at run time. The entry that comes back keeps its snake_case field names. |
| `physicsSearch` on the package root. | `physicsSearch` from `hippo-memory/store-kit`, with the same signature. To rank recall by physics without calling it, set `physics.enabled` to `'auto'` or `true` in config. |
| A `HippoStore` could leave any store group unset, and each route or MCP tool that named a missing group answered 501. | Set every group. Only `localFiles`, `vectorViews`, `readiness` and `lastRecall` may stay unset; a store without any other group is now a type error. A store that serves only some groups can spread `sqliteStore(hippoRoot)` and replace the groups it serves: under `serve()` the rest reach a fenced hippo.db and answer 501 `store_not_ported`, as before. A route or tool that needs one of the four optional groups still answers 501 on a store without it. |
| `narrowStore`, `StoreWith<G>` and `ContextWith<G>` from `hippo-memory/store-kit`. | `HippoStore` in place of `StoreWith<G>`, and `Context` (from `hippo-memory/server`) in place of `ContextWith<G>`. Drop each `narrowStore` call: every required group is already set. For one of the four optional groups, call `requireGroup(store, group)`, which returns the group or throws `StoreNotPortedError`, a 501. |
| `Context.store` was optional, and an entry handed a `Context` without one opened hippo.db under `hippoRoot`: `sleep` on the package root, and `authCreate`, `authCreateSelf`, `authRevoke` and `promptHookContext` on `hippo-memory/server`. | `Context.store` is required. Build the store once and put it on the `Context`, for example `store: sqliteStore(hippoRoot)` from `hippo-memory/store-kit`; a `Context` without `store` is a type error and fails at run time. |
| `HippoDbContext` and `StoreContext`, exported from `hippo-memory/store-kit`, which named a `Context` with and without a store. | Use `Context`, exported from `hippo-memory/server`. Every `Context` now carries its store, so the two names are gone with no alias. |
| An add-on route's `storeReady` gated the route on any store group. | Name one of the four optional groups, or `base`. A required group is always set, so naming one gates nothing. Unset, `storeReady` still means `localFiles`, so the route answers 501 on any store but hippo.db. |
| `graphExpandRecall(results, { hippoRoot, globalRoot?, tenantId, ... }): SearchResult[]` on the package root, which read hippo.db under each folder. | `graphExpandRecall(results, { store, global?, tenantId, ... }): Promise<SearchResult[]>`, with `store` and `global` as `HippoStore`s, for example `sqliteStore(hippoRoot)`. Await the result. The walk reads through three new `GraphReads` methods, `entitiesForMemories`, `entitiesByIds` and `neighborRelations`, so a store you build on `hippo-memory/store-kit` must implement them; `sqliteStore` already does. |
| A `GraphReads` group with no `storedGraph` method. | Add `storedGraph(tenantId, memoryIds)`, which answers `{ kinds, entities, relations }`: the tenant's entities and relations, each in id order with hippo.db's snake_case column names, and a map from each of `memoryIds` to its memory's kind, in whichever tenant the memory sits. Sleep's graph rebuild reads its diff through it. `sqliteStore` already has it. |
| `initStore`, `writeEntry`, `loadAllEntries`, `readEntry`, `deleteEntry`, `loadSearchEntries`, `loadRecallEntries`, `loadSessionDecayContext`, `loadIndex` and `rebuildIndex` on the package root, which took a folder, opened hippo.db and skipped the tenant, actor and audit checks. | `hippo init`, `hippo remember`, `hippo recall` and `hippo forget`, or `POST /v1/memories`, `GET /v1/memories` and `DELETE /v1/memories/:id` on `serve()`. A store you build reads and writes rows through the groups of `HippoStore`, for example `sqliteStore(hippoRoot)` from `hippo-memory/store-kit`. `loadIndex` and `rebuildIndex` have no replacement: no hippo path writes `index.json` any more, and opening a store whose hippo.db holds no memories still imports legacy markdown mirrors. |
| The session, conflict, handoff and card functions on the package root: `appendSessionEvent`, `listSessionEvents`, the `*ActiveTaskSnapshot` and `closeTaskSnapshotsForSession` functions, `loadFreshActiveTaskSnapshot`, `saveSessionHandoff`, `loadLatestHandoff`, `loadHandoffById`, `stampHandoffOutcome`, `writeSessionEndHandoff`, `listMemoryConflicts`, `replaceDetectedConflicts`, `resolveConflict`, `createCard`, `loadCard`, `listCards`, `claimCard`, `heartbeatCard`, `blockCard`, `reviewCard`, `completeCard`, `reclaimExpiredCards`, `addCardComment`, `loadCardRuns`, `loadCardDeps`, `loadCardComments`, `loadLatestHandoffForCard` and `SNAPSHOT_AMBIENT_MAX_AGE_MS`. | `hippo session`, `hippo snapshot`, `hippo handoff`, `hippo conflicts`, `hippo resolve` and `hippo card`. Cards have no HTTP route. The card and handoff types and constants from `src/core` stay on the root. `loadCardDeps`, `loadCardComments` and `loadLatestHandoffForCard` are gone: `hippo card show --json` prints a card with its dependencies, comments and latest handoff. |
| `embedMemory`, `embedAll`, `cosineSimilarity`, `loadEmbeddingIndex` and `saveEmbeddingIndex` on the package root. | `hippo embed` embeds a store, and `hippo remember` embeds a new memory on its own where a model is installed. `isEmbeddingAvailable` and `getEmbedding` stay on the root. For a similarity score, take the dot product of two `getEmbedding` vectors. |
| `fetchGitLog`, `runWatched`, `runWatchedLine`, `deduplicateLesson`, `autoShare`, `shareMemory`, `promoteToGlobal`, `syncGlobalToLocal`, `listPeers`, `initGlobal`, `searchBoth` and `searchBothHybrid` on the package root. | `hippo learn --git`, `hippo watch`, `hippo share`, `hippo promote`, `hippo sync`, `hippo peers` and `hippo init --global`, or `POST /v1/memories/:id/promote` on `serve()`. `deduplicateLesson` and `searchBoth` are deleted with no replacement; `hippo recall` searches the local and global stores together. `captureError`, `extractLessons`, `partitionLessons`, `transferScore` and `getGlobalRoot` stay on the root. |
| `wmPush`, `wmRead`, `wmClear`, `wmFlush` and `WM_MAX_ENTRIES` on the package root. | `hippo wm push`, `read`, `clear` and `flush`. The cap is 20 entries per scope. |
| `appendAuditEvent`, `queryAuditEvents`, `listAuditEventsAfter` and `AUDIT_OPS` on the package root. | `hippo audit list` and `GET /v1/audit` on `serve()`. |
| On/off variables read only as `1`, `true`, `on`, `0`, `false` or `off` (any case). Before, some read only `1` and `HIPPO_REQUIRE_AUTH=true` read as off. | Spell flags `1`/`true`/`on` or `0`/`false`/`off`. Any other spelling takes the safe side (`HIPPO_REQUIRE_AUTH` on, every other flag off), and `hippo serve` refuses to start on one, naming the variable. The CLI and postinstall warn and carry on. `HIPPO_AUTODEBIAS`, `HIPPO_ANCHORING` and `HIPPO_AVAILABILITY` now also turn off for `0` and `false`. |
| Secret-shaped text typed by a person (`hippo remember`, `POST /v1/memories`, the MCP remember tool, the importers) was stored as sent, with a warning. Only connector and imported text was redacted. | Every caller's text is redacted with the strict rules before it is stored, and the reply carries the "redacted before storing" warning. To keep a value, hold it outside hippo and store a pointer to it. `vetSecrets` takes the content alone. |
| `HIPPO_TRUSTED_PROXIES=*`, which trusted the client-IP header from any peer and only logged a warning. | List the proxy's addresses or CIDRs. `serve()` now refuses to boot on `*` (`WildcardTrustedProxiesError`), with or without `HIPPO_CLIENT_IP_HEADER`. `deploy/aml` pins its compose network and lists that subnet. |
| `HIPPO_KEYLESS_LOCAL_ROLE=admin`, which made a keyless local caller (`HIPPO_ALLOW_KEYLESS_LOCAL=1`) the host admin. | Nothing reads it. A keyless local caller is always a member; mint an admin key (`hippo auth create --role admin`) for sleep, the quarantine routes and cross-tenant reads. |
| The `keylessLocalRole` option of `serve()`, and `envKeylessLocalRole` in the source. | Removed with the variable. Mint an admin key and send it as `Authorization: Bearer <key>`. |
| A second `serve()` on one store could start when the two booted together, because the pidfile was written after the bind. | None needed. `serve()` now claims `server.pid` with exclusive create before it binds, so exactly one boot wins and the other fails with the "already running" error. A pidfile whose pid is a live process of another user (EPERM) now counts as alive. |
| `runWatched(argv, deadlineMs, { shell: true })` and the `RunWatchedOptions` type, which joined argv with spaces into one unquoted shell line. | `runWatchedLine(line, deadlineMs)` for a line you wrote yourself, or `runWatched(argv, deadlineMs)` to pass each argument literally. |
| Context reads past the cap ranked every row of the tenant. | None needed. hippo.db moves to schema 60 on first open, which builds the index `idx_memories_decay_key` (about 50 ms and 1.3 MB for 50,000 memories). `loadContextCandidates` reads through it and returns the same rows in the same order. This branch skips schemas 57 to 59 until they land, and `prepublishOnly` fails while the numbers have that gap. |
| The `energy` figure at the end of the physics line in `hippo sleep` output. | `hippo status`, which prints the energy with its kinetic and potential parts for up to 2,000 particles. |
| The flat `RecallOptions` of `retrieve` in `src/api`, one bag of 20 optional fields, for example `retrieve(ctx, { query: 'deploy', limit: 5, scope: 'team', sessionId: 's1', explain: true })`. | The same fields in five parts named for the stage that reads them; `query`, `mode`, `showRanked` and `cliCore` stay at the top. `window` holds `limit`, `scorerWindow`, `summarizeOverflow`, `freshTailCount`, `freshTailSessionId` and `includeContinuity`; `filter` holds `scope`, `project` and `keepHeldCopies`; `boost` holds `sessionId` and `goalTag`; `hints` holds `recallHistory` and `suppressAvailabilityHint`; `trace` holds `explain`, `suppressRecallTrace`, `leadingAudit` and `recordAs`. The example becomes `retrieve(ctx, { query: 'deploy', window: { limit: 5 }, filter: { scope: 'team' }, boost: { sessionId: 's1' }, trace: { explain: true } })`. `cliCore.rank` takes `window: { limit }` in place of `limit`, and the boost from the top-level `boost`. The HTTP query string, the MCP tool arguments and the CLI flags do not change. |
| A `HippoStore` with no `rejections` group: `hippo reject`, `hippo unreject`, `hippo rejections` and the importers' dry run opened hippo.db under the store's folder. | Add `rejections`, typed `Rejections` in `hippo-memory/store-kit`: `apply(rejection)` writes the tombstone and removes every row in reach that holds the text, `lift(tenantId, digestPrefix, actor)` and `list(tenantId)` lift and list tombstones, and `refusedAmong(checks)` says which writes the guard would refuse, writing nothing. `heldTexts` and `normalizeValueForRejection` are exported beside it so a store finds held text with hippo.db's rule. `sqliteStore` already has the group. |
| A `connectorEvents` group with only the delivery methods: the Slack and GitHub backfill cursors, the dead-letter list, row read and retry count, and the Slack workspace registry opened hippo.db under the store's folder. | Add eleven methods to `connectorEvents`: `deadLetters(connector, tenantId, limit)`, `deadLetter(connector, id)` and `markDeadLetterRetried(connector, id)` for either queue; `slackCursor`, `saveSlackCursor`, `githubCursors`, `saveGitHubHwm` and `seedGitHubCursors` for backfill; `slackWorkspaces`, `registerSlackWorkspace` and `removeSlackWorkspace`. `sqliteStore` already has them. `addWorkspace`, `listWorkspaces`, `removeWorkspace` and `listDlq` in `src/connectors` now take a `HippoStore` and return a Promise. |
| A `HippoStore` with no `failureLog` group: the tool-failure hook and `captureFailureForCaller` wrote and read the failure log in hippo.db under the store's folder. | Add `failureLog`, typed `FailureLog` in `hippo-memory/store-kit`: `record(event)` prunes rows past 90 days, appends one and answers its id; `requestOutcome(tenantId, requestId, sessionId)` answers the outcome logged under a request id, or null, and rejects with `ConflictError` when another session logged it; `settleOutcome(tenantId, requestId, outcome)` rewrites that outcome. `FailureEvent` and `FailureOutcome` are exported beside it. `sqliteStore` already has the group. |
| A `lessonWrites` group with no `contentsWithTag` method. | Add `contentsWithTag(tenantId, tag, origins?)`, which answers the contents of the tenant's rows tagged `tag` that the default recall scope admits; with `origins`, only rows of those projects and user-global rows (empty `origin_project`). The failure hook's repeat check reads through it. `sqliteStore` already has it. |
| `captureFailureForCaller(ctx, req)` on `hippo-memory/server` returned its result. | It returns a Promise of the same result, and reads and writes through `ctx.store`. Await it. |
| A `reports` group with no `stats`, `statusCounts`, `correctionEntries`, `rawEntries` or `createdSinceLastSleep`: `hippo status`, `hippo correction-latency`, `hippo provenance` and the auto-sleep trigger opened hippo.db under the store's folder. | Add five methods to `reports`: `stats()` answers the lifetime counters and the newest 50 sleep runs; `statusCounts(now, atRiskBelow)` answers what `hippo status` counts over every row of every tenant, typed `StatusCounts`; `correctionEntries()` answers every superseded row, its successor and that row's extraction source; `rawEntries()` answers every `kind = 'raw'` row; both by created then id. `createdSinceLastSleep(tenantId, now)` counts the tenant's rows created since the last sleep, looking back at most a day. `StatusCounts` and `LegacyStats` are exported beside it. `sqliteStore` already has them. |
| A `contextReads` group with only the context and ambient reads: `hippo remember`'s schema fit and salience window, the session digest's read of earlier digests and `hippo import vault`'s read of a vault's rows opened hippo.db under the store's folder. | Add four methods to `contextReads`: `newestEntries(tenantId, limit)` answers the tenant's `limit` newest rows, oldest first; `schemaFit(tenantId, content, tags)` answers `computeSchemaFit` against the tenant's newest 2,000 rows; `liveContentsBySourceAndTag(tenantId, source, tag, exceptSessionId)` answers the contents of live rows from `source` tagged `tag` that no extraction produced, less one session's; `rawRowsUnderRef(tenantId, refPrefix)` answers the tenant's raw rows whose `artifact_ref` starts with `refPrefix`, exact case, typed `RawRefRow`. The last three answer by created then id. `sqliteStore` already has them. |
| `AuditMaintenance.tenantEntries(tenantId)` and `Consolidation.allEntries()`, which read every memory of a tenant or of the store in one array. | Nothing calls them since sleep and the audit read in pages; drop them from your store. A pass that needs every memory reads `Consolidation.entriesPage` until `next` is null. |
