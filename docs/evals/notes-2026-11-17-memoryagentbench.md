# Dated notes, 2026-11-17: MemoryAgentBench as its authors' suite runs a memory method

Post hoc and secondary, like lanes F and D (prereg Amendment 6, dated notes 30 and 31). No registered result changes.

**Why.** MemoryAgentBench (Hu, Wang and McAuley, arXiv 2507.05257, ICLR 2026) prints one table (Table 3) with six memory products on one setup: Mem0, Cognee, Zep, MemGPT (Letta), MIRIX and HippoRAG-v2, next to BM25 and long-context models. Each product row has 10 task columns, four competency averages and an Overall. Keith (17 Nov): every public benchmark runs in its published setup, so hippo's row sits next to these on equal terms. The repo documents no plug-in point for a new memory method. Upstream merged three third-party methods (knowl and agentmemory in `d61de5e`, total-agent-memory in `c2a18f0` and `4704962`). All three store the suite's chunks and answer through the suite's BM25 reader, `_handle_bm25_rag`. This lane does the same with hippo in place of BM25.

LME(S\*): `get_anscheck_prompt` over the raw question, answer and reply, abstention when the question id holds `_abs`, one user message to `gpt-4o-2024-08-06` at temperature 0 and `max_tokens` 10; correct when the stripped reply holds "yes". InfBench-Sum: the three book prompts (fluency, recall over numbered keypoints, precision against the first answer), each one user message to `gpt-4o-2024-08-06` at temperature 0.1, `top_p` 0.9, seed 42, `max_tokens` 4096; `parse_json` on each; F1 times fluency. A summary whose call or JSON fails is left out of the mean, as the script leaves it.

**Deviations that stay.**
- Reader. No product row used one shared reader. Mem0 used its own prompt over its top 100 memories; Zep ran on Azure and Zep's cloud; Cognee returned its own answer; MIRIX has no code in the repo. Hippo uses the BM25 reader, as the three merged methods do. Hippo's row is "hippo's retrieval under the suite's RAG reader".
- Snapshots. The code sends the aliases `gpt-4o-mini` and `gpt-4o`. We pin `gpt-4o-mini-2024-07-18` (the alias serves it, dated notes 30) and `gpt-4o-2024-08-06`.
- Summary judge. The code uses `gpt-4o-2024-05-13` through the Batch API. That snapshot is in neither free pool, so every call would bill. We use `gpt-4o-2024-08-06`, called one at a time, with the same prompts and sampling settings.
- Data revision. The code loads revision `main`; the paper does not say which. The dataset changed after the first version (9 Sep 2025, LME(S\*) contexts 3 and 4 deduplicated; 29 Sep, samples removed; 7 Oct, short-context samples added). We pin `7ea06698`.
- Run list. `rag_agents.txt` leaves out Detective QA; Table 3 has it, so we run it.
- Sampling. The answer runs at temperature 0.7, so it varies run to run. The paper made one answer per question, and so do we.
- Failed calls. The suite skips an answer whose call returned nothing. Here each item takes the first valid reply in 3 asks (`qa/ledger.py`); an answer with none scores 0 and is listed.
- Time stamps. The memorize template's time stamp is the time of `prepare`, not of each add.
- Embedding. hippo embeds each 4096-token memory with its own model, which reads only the start of a long text. That is hippo's behaviour, kept.

**Order.** `prepare --regime memory`; for `hippo-emb`: `ingest`, `retrieve`, `answer`, `judge`, `score`; then `bm25`; then the `rag` regime. Five questions run first as a smoke, seeded (`SMOKE_SEED` 20261117): one LME(S\*), one InfBench-Sum, one from an AR document task, one TTL, one SF. The smoke writes integrity counts and tokens only, never a score. Its questions are the `memoryagentbench` key of `smoke_excluded.json` and stay out of the primary.
Smoke items, excluded: `lme-c000-q012`, `infbench_sum-c025-q000`, `sh_qa-c000-q043`, `icl_nlu-c000-q027` and `fc_mh-c000-q059`. They are the five the seed picks from the 2,071 prepared questions.

**Tests.** `tests/test_mab_hippo.py`. They fail if `official.py` changes or stops matching a fresh cut of the pinned clone, if a task leaves its shipped data config, if the reader leaves the BM25 agent config, if the answer or either judge leaves with another model, temperature, `top_p`, seed, token limit or message shape, if a judge prompt fills differently from the script, if the averages stop rebuilding Table 3, if an exhausted answer stops scoring 0, or if the smoke stops covering every competency.

**Calls.** `estimate` counts the prompts a full run sends (o200k, with `openai_llm`'s framing), each answer at 10 memories of its context's mean wrapped-chunk size, each judge with the answer at its cap. Regime `memory`, one arm: small pool 85.9M in and at most 0.38M out; big pool 1.35M in and at most 1.23M out (every judge reply at its cap). Regime `rag`: small pool 60.6M in, the big pool the same. With the whole free small pool, one arm of `memory` takes about 35 days and one of `rag` about 25; the big pool needs 5.4 to 10.3 days. At list price one `memory` arm is about $13.1 of gpt-4o-mini and $3.4 to $15.7 of gpt-4o. No paid call: the free-token cap of dated notes 30 holds every call.
