## Why this size

`node design.mjs` prints the replay cells, assumptions, required pairs and achieved power. The underlying file is `experiment1/data/end-check-prod-replay.json`. The production replay listed 7 of 9 omitted lessons, and listed the target on 0 of 37 omission passes and 0 of 131 passes across all lesson types. There were 24 other-rule listings at first applies. Across the larger replay it listed something in 164 of 1,077 sessions (15.2%). The denominators differ. The latter figure estimates reminder burden. It cannot supply the failure-reduction effect.

The frozen manifest retains 7 replay-listed failures among 45 eligible omission cases. With half repaired, the planning net reduction is 7.78 points. Assign 4% reverse discordance and 11.78% favourable discordance. Under independent pairs the one-sided sign test reaches 80% power at 174 pairs. The 16 seed-one cases give 2.0% power, one block gives 21.7%, and four complete blocks give 81.4%. The repeated blocks estimate the effect on these same historical cases.

**Family sensitivity.** `node design.mjs` joins each listed failure to the eligible family, seed and position. The seven cases fall in four families, with three in q118-f2 and two in q173-f3. For each simulated trial, draw one repair probability per listed family, shared by every case and block in it. On each pair, harm has probability .04, gain has probability .04 plus that family's repair probability for a reachable case, and the remainder is concordant. Equally likely weak/strong family probabilities of .1/.9 retain the same mean repair and give 74.0% power. If half of the listed families no longer reproduce their omissions on the newer binary and the rest repair half the time, using 0/.5 gives 38.9%. These are assumptions about transfer. The binary's repair rate is unknown. The script fixes the simulation seed at 20261125 and runs 20,000 trials per scenario. Enrollment stays fixed for all scenarios.

For safety, enumeration in the same command gives a 57.6% chance of clearing the margin at zero net harm when each discordant direction has 4% probability. The secondary assessment can therefore remain unresolved even if the hook is harmless.

The design assigns **546 real Opus applies**, comprising 180 omission pairs and 93 additional safety pairs. No live teach, preparation, grading or raw API model call is needed for the full trial. Claude Code can make multiple internal turns within an apply. Confirmed limit interruptions can add attempts. Each separately authorised qualification uses at most one additional, unscored ON apply.

## Measurement and exclusions

Grade both first tries after any Stop-induced continuations and before any human feedback. Use the frozen Z0 command log (main and subagents), the observed pre/post Git trees and the original checker. The outcome assessor uses the same function and inputs in both arms. Pair gains count OFF fail / ON pass. Pair harms count OFF pass / ON fail. The primary estimate is (harms minus gains) / omission pairs. The exact one-sided sign test conditions on gains plus harms. Its inference is conditional on this set of tasks and independent order assignments under the sharp null. Show family-level counts to expose concentration.

For historical passes, report both live failure counts, gains and harms. The secondary estimand is (harms minus gains) / pairs. The one-sided approximate 95% paired score upper limit in `safety.mjs` inverts the trinomial score test. At each candidate difference it fits the discordance probability subject to that difference and uses the constrained variance of the paired differences. It handles zero discordance at the parameter boundary. Correlated families and small discordance counts limit the nominal coverage. Also report sessions receiving a target reminder, false target reminders, and other-rule reminders separately. A target matches the frozen current lesson's key phrase or the leading normalised rule text, as in the replay. A false target listing means the checker already returned pass or inapplicable on the live command history and tree at that Stop. A historical pass can legitimately omit the action this time. A final pass after the reminder can be a repair. Neither alone makes a listing false. Other rules are counted without assigning them the target's grade. Multiple listings count once per session in each rate.

The ON shim executes the installed production command once and forwards its stdout unchanged. Stamped events must match the actual Stop additional-context attachments. A Stop that returns empty output, an ignored reminder and an inner production Stop timeout all retain their assigned arm and grade.
