Hippo fixes the step where built-in memory breaks. It stores the lesson every time and shows it 95% of the time, against 57% for built-in memory. When any arm shows a lesson, the agent follows it 96 to 98% of the time. So the open question is not recall. It is why showing the lesson 38 points more often cuts repeat mistakes by only 12 points.

Grading defects found, and what they touch

  • Final checks of command rules (Amendment 5). No authored checker reads CHECK_RESUME_COMMANDS, so a final check fails every corrected session whose first session broke a command rule. This touches only set R's resolved status. Set R's resolve rate and cost per resolved task are therefore understated, more so in an arm that needs more corrections, and are not read as evidence for or against hippo.
  • fk-f3-l1 (Amendment 6). The checker passed one -n per added test, and minitest 6.0.6 keeps only the last, so it could fail a session that did write a failing test first. It was fixed, every arm of fk was re-graded with regrade --post-fix, and fk drew a new reader round. Both of fk's round 1 disagreements cleared, and round 2 scored 0 of 5.
  • Final-check reader pairs. 13 of 35 final-check pairs disagree, which is the Amendment 5 defect above. G5 reads first-check pairs only.

What this means for hippo

  • The run is valid, and installing hippo cut repeat mistakes against built-in memory. The cut is real but smaller than the 15 points the prereg asked for.
  • It cost about 10% more tokens overall and 12% more on tasks with no lesson. That breaks the harm gate.
  • The sham arm keeps hippo's prompt and injection but drops capture. A2 beats it under one coding and not the other, so this run cannot credit the gain to hippo's own lessons.
  • The next lever is first-session cost: trim what hippo injects when no lesson matches. The chain says recall is already at 95%.
